# Generative UI QA

Date: 2026-11-01. Branch `feat/generative-ui`. Worktree `~/orbit/.worktrees/genui`.

The chat renders every catalog component, survives bad specs, keeps a failed thread usable, and restores generated UI after a reload. The real provider call returned a card, a metric, and a list. Mobile layout is the one open problem, recorded in `docs/qa/visual-findings.md` for a design pass.

- Node v26.13.0, npm 11.20.0.
- Next.js 16.4.3, production build.
- Playwright 1.64.1, headless Chromium, installed through npx.
- App at `http://127.0.0.1:3213`. Mock provider at `http://127.0.0.1:3299/v1`.
- Sandbox database at `/tmp/orbit-genui-qa`. The repo `data/` directory was not used.
- Viewports: 1440x900 and 390x844.
- Real model: `deepseek-v4.1-flash` through `https://opencode.ai/inference/go/openai/v1`. The key was read from `~/kodus/.env` in the shell, passed as `ORBIT_REAL_API_KEY`, and not printed. The settings response was checked for the key and did not contain it.

## Method

`scripts/qa/mock-provider.mjs` is a local OpenAI-compatible server. It streams one `render_ui` tool call per request. The scenario comes from a `[qa:<name>]` token in the last user message.

`scripts/qa/genui-qa.cjs` signs up or signs in, creates a chat per scenario, sends the prompt, checks the rendered DOM, takes desktop and mobile screenshots, reloads, and writes findings to `/tmp/orbit-genui-qa-report.json`.

The scenarios are:

| Scenario | What it sends |
| --- | --- |
| all | Card, Metric, KeyValue, Table, List, Text, Callout, Button |
| huge | 220 rows by 8 columns |
| long | Long paragraph, long unbroken word, long code, long table cells |
| invalid | Card title is a number |
| missing | Metric without a value, Callout without a tone |
| unknown | Element type `Chart` |
| dangling | Card child key that does not exist |
| malformed | Tool arguments that are not valid JSON |
| truncated | Stream stops in the middle of the arguments |
| text | Text component only |
| recover | Plain assistant text after each failure |

## Functional fixes

### 1. Replies were stored on a local thread id

Commit `0bf029b`.

The first browser run sent `/api/chat` with `__LOCALID_...` instead of the id in `/c/<id>`. The route created a new chat for that local id, stored the assistant reply there, and the page reload found nothing. Two UUID chats stayed empty. The smoke script missed this because it posts to `/api/chat` directly with the chat id.

`ChatPanel` now sets `prepareSendMessagesRequest` and passes the open chat id in the body. Reload shows the same messages.

### 2. A follow-up duplicated the assistant message

Commit `0bf029b`.

The server stored the assistant reply under its own generated id. The client kept a different id. The next send included the client id, and `upsertMessage` inserted a second copy. The invalid, unknown, and truncated chats had two copies of the same tool part before the fix.

`upsertMessage` now updates the latest identical assistant row when the client sends its own id, instead of inserting a duplicate. The QA run checks the assistant count after a follow-up and a reload.

### 3. The build raced its own database migration

Commit `cf7f84a`.

`npm run build` failed intermittently with `table account already exists`. Fifteen page-data workers imported the database module at the same time and each ran the Drizzle migration. The first clean build after the lock change passed twice.

`src/lib/db/index.ts` now takes a `data/.migrate.lock` file lock around `migrate`. A stale lock older than 30 seconds is removed. `ORBIT_DATA_DIR` selects the data directory, and `ORBIT_TRUSTED_ORIGINS` adds auth origins for a test run. Defaults are unchanged.

### 4. An unknown component showed a generic provider error

Commit `bd8b5c7`.

The catalog schema rejects an unknown element type before `parseRenderSpec` runs. The stream error handler replaced the reason with `The model request failed`, so the fallback said the provider failed when the spec was wrong. The handler now returns the tool input error text with the `AI_...Error` prefixes removed. The fallback shows `Invalid input for tool render_ui` and the raw spec. The thread stays usable.

### 5. Generated text and code were read-only

Commit `3477402`.

The catalog has a `Text` component with `content`, `label`, and `format` (`plain` or `code`). Its content is a `contentEditable` textbox with an accessible role and label. The value is escaped before it enters the DOM. Edits stay in the component and do not touch the spec, so validation is unchanged. A reload shows the original generated text.

Unit tests cover a valid Text spec, an invalid format, and the rendered textbox.
