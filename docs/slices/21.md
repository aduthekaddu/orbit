# Slice 21. Artifacts page

Keep every artifact the model writes, with a title you can change, linked versions, and a page that finds any of them. A download takes the artifact's title as its file name.

**Branch** `feat/artifacts-page`. **Depends on** [slice 16](16.md) for the artifact card in the thread, and [slice 18](18.md) for accounts and the cross-user route test.

## Why

An artifact exists today only while its message is on screen. `CodeHeader` registers each HTML, SVG, or React block in a React state map when it renders (`src/components/chat/code-block.tsx:58-61`, `src/components/artifacts/use-artifact.ts:23-39`). Nothing stores it. To find last week's chart you have to remember the chat, scroll to it, and be on the right branch. Every download is named `artifact.<language>` (`src/components/artifacts/artifact-panel.tsx:114`). A regenerate makes a new version, but nothing links it to the old one, and the only way back is the branch picker.

Claude.ai users lost their saved artifact versions when a menu item disappeared ([anthropics/claude-code#96718](https://github.com/anthropics/claude-code/issues/96718)). Orbit keeps the versions list on screen.

## Scope

Ships:

- An `artifacts` table, filled when a reply is saved or edited, with a backfill for existing chats.
- A title derived from the code, and rename.
- Versions linked across regenerate and edit branches, shown in a list that stays visible in the chat panel and on the page.
- Downloads named after the title.
- An `/artifacts` page with search, preview, versions, rename, download, and a link to the chat.

Does not ship:

- Deleting an artifact. It lives in a message, and removing it would edit the reply.
- A diff between versions.
- Publishing one artifact on its own. [Slice 22](22.md) shares whole chats.
- Artifacts in the command palette search.

## Design

### Data shape

```ts
type ArtifactLanguage = "html" | "svg" | "jsx" | "tsx"; // src/lib/artifacts/detect.ts:3

type ArtifactRow = {
	id: string; // UUID
	userId: string;
	chatId: string;
	messageId: string; // the assistant reply that holds the block
	textOrdinal: number; // which text part of the reply, counting text parts only
	blockIndex: number; // which code block in that part, counting every block
	language: ArtifactLanguage;
	code: string;
	derivedTitle: string; // from the code, updated whenever the code changes
	userTitle: string | null; // set by rename, read only from the lineage's first row
	lineageId: string; // the id of the first version
	createdAt: Date; // the reply's created_at, so versions sort the way the chat grew
	updatedAt: Date;
};

type ArtifactVersion = { id: string; number: number; messageId: string; key: string; createdAt: Date };
```

The key the client already uses is `` `${messageId}.${textOrdinal}.${blockIndex}` `` (`code-block.tsx:55-57`). The row stores the three parts as columns, with a unique index on `(message_id, text_ordinal, block_index)`, so a row maps to exactly one rendered block. `?artifact=<key>` links and `artifactHistory` (`src/lib/artifacts/history.ts:5-13`) keep working unchanged.

The shown title is the lineage root's `user_title`, or else the row's `derived_title`. A rename writes only the root row. That keeps one source of truth for the name of a whole lineage without a second table.

Columns in `src/lib/db/schema.ts`. `user_id` references `user.id`, `chat_id` references `chats.id`, and `message_id` references `messages.id`, all on delete cascade. Indexes on `(user_id, updated_at)`, `(lineage_id)`, and `(chat_id)`.

`artifacts_fts` is an external-content FTS5 table over `derived_title`, `user_title`, and `code`, with insert, update, and delete triggers. It copies the `messages_fts` pattern from slice 6. Generate it with `npx drizzle-kit generate --custom`, as `AGENTS.md` says for FTS5.

### Finding artifacts in a reply

`extractArtifacts(parts)` in `src/lib/artifacts/extract.ts` is a pure function.

1. Walk the reply's parts. Each `text` part gets a `textOrdinal` that counts text parts only. This matches how `MarkdownText` counts them (`src/components/chat/markdown-text.tsx:82-86`).
2. Parse each text with `unified().use(remarkParse).use(remarkGfm)`, the same GFM plugin the client uses (`markdown-text.tsx:74`).
3. Number every mdast `code` node in document order. That is `blockIndex`. `rehypeCodeBlocks` numbers every `pre` that holds a `code` element (`src/lib/markdown-code.ts:8-23`), which is the same set. A Python block between two HTML blocks still takes a number.
4. Keep the nodes whose `lang` passes `isArtifactLanguage` (`detect.ts:11-13`).

`unified` 11.0.5 and `remark-parse` 11.0.0 are already installed as dependencies of `react-markdown`. Add both to `dependencies` at those versions. A parity test runs the same text through `remark-rehype` and `rehypeCodeBlocks` and checks that the indexes match. The browse scenario also checks that the server key equals the key on each rendered card.

### Titles

Slice 16 creates `artifactTitle(artifact)` and `artifactFileName(artifact)` in `src/lib/artifacts/title.ts`, with their rules and tests. This slice reuses both and adds no second title function and no `title` column. The sync and `backfillArtifacts` write `artifactTitle(...)` to `derived_title` on every insert and every code change. A rename writes `user_title` on the lineage root, as the data shape says. The shown title is the root's `user_title`, or else the row's `derived_title`, and one helper, `shownTitle(row, root)` in `store.ts`, computes it for the card, this page, and the download. Extend `artifactFileName` with an optional `title`, and pass the shown title, so a renamed artifact downloads under its new name.

### Linking versions

`lineageFor(artifact, tree, earlier)` in `src/lib/artifacts/lineage.ts` is a pure function. `tree` is the chat's messages with `parentId`. `earlier` is the chat's artifacts saved before this one. Let `P` be the reply's prompt and `G` the prompt's parent.

1. **Relatives** are artifacts of the same kind in replies on the path to `P`, in other replies to `P` (regenerates), and in replies to any other user message under `G` (edits of the prompt).
2. **Same title.** If a relative has the same derived title, ignoring case, join the newest such lineage. This covers a follow-up such as "make the button blue" when the model keeps `<title>`.
3. **Same place.** Else, if `P` has other replies or other edited versions, take the most recent of those replies. Join the lineage of its artifact at the same position among that reply's artifacts.
4. Else start a new lineage, with `lineageId` set to the new row's id.

A version's number is its rank in the lineage by `created_at`, then by `rowid`.

### When rows are written

`syncMessageArtifacts(userId, chatId, messageId, parts, tx)` in `src/lib/artifacts/store.ts` runs inside the existing message transactions:

- In `finishChatReply` (`src/lib/messages.ts`). That covers new replies, regenerates, and stopped replies with visible text.
- In `updateMessageText` (`src/lib/messages.ts:214-229`). That covers the inline code editor and the reply editor, through `PATCH /api/chats/[id]/messages/[messageId]` (`src/app/api/chats/[id]/messages/[messageId]/route.ts:21`).

It compares the extracted list with the message's rows by key. It updates the code and derived title of a row whose key still exists, inserts new keys with `lineageFor`, and deletes keys that are gone. If a deleted row is a lineage root with later versions, the next version becomes the root. Its id becomes the new `lineage_id` for the rest, and it takes the old `user_title`. Running the sync twice with the same parts changes nothing.

An edit that adds or removes a block before another block shifts that block's `blockIndex`. Its row is then deleted and a new row is inserted with a new id. A rename on a moved block that was a lineage root survives through the promotion step. A rename on a later version is not lost, because renames live on the root.

### Backfill

`backfillArtifacts()` runs at start from `src/instrumentation.ts:1-7`, after the database import, only while `instance_settings.artifacts_backfilled_at` is null. This slice adds that nullable integer column to slice 18's table. The backfill selects assistant messages whose `content` contains a fence, `` ``` `` or `~~~`, and lets `extractArtifacts` decide which blocks are artifacts. A narrower filter on tags such as `` ```html `` would miss `` ``` html ``, which CommonMark reads as the same `html` block and the client already renders as an artifact. It processes the messages per chat in `created_at` order, so linking sees earlier versions first, and commits every 200 messages. When it reaches the end it sets `artifacts_backfilled_at`, so the next start does nothing, even for messages whose fences hold no artifact. A crash before the end reruns the whole pass on the next start, which is safe because the sync is idempotent. Replies saved after this slice ships go through the sync and never need the backfill. The `LIKE` here filters text content. It is not an identity lookup.

### Routes and helpers

Every helper takes `userId` first: `listArtifacts(userId, { q, cursor })`, `getArtifact(userId, id)`, `listVersions(userId, lineageId)`, `listChatArtifacts(userId, chatId)`, `renameArtifact(userId, id, title)`.

- `GET /api/artifacts?q=&cursor=` returns one row per lineage, its newest version. Each row has the title, kind, chat title, chat id, updated date, and version count. With `q` it searches `artifacts_fts` using `toMatchQuery` from `src/lib/search.ts:26-35`.
- `GET /api/artifacts/[id]` returns the artifact and its versions.
- `PATCH /api/artifacts/[id]` with `{ title }` parsed by zod (1 to 80 characters, trimmed) renames the lineage. An empty title clears `user_title`.

Each returns `404` for another user's id. The ids are UUIDs, so no URL ends in an extension and the matcher in `src/proxy.ts:34` cannot skip one. Downloads stay in the browser as a `Blob`, as `artifact-panel.tsx:110-117` does now, so no download route is needed.

### UI

In the chat:

- The chat page loads `listChatArtifacts(userId, chatId)` and passes a map from key to `{ id, title, lineageId, number, versions }` into `ArtifactProvider`.
- The artifact card from slice 16 and the panel header show the stored title. A pencil next to the panel title renames it inline. Enter saves and Escape cancels.
- `ArtifactVersions` sits in the panel under the header, always visible, as a row of `v1`, `v2`, `v3` buttons in `num`, inside `ScrollFade axis="x"`. The current version is a raised surface. A version on the open branch switches the panel with `open(key)`. A version on another branch navigates to `/c/<chatId>?m=<messageId>&artifact=<key>`. The `m` value remounts `ChatPanel` (`src/app/(app)/c/[id]/page.tsx:40`) on the branch that holds it, the way search results already jump.
- **Download** uses `artifactFileName` with the shown title.

The page:

- `/artifacts` sits in the app shell. Add **Artifacts** to the palette next to **Memory** (`src/components/shell/command-palette.tsx:116`), to the header title in `src/components/shell/app-shell.tsx:107`, and to the drawer links slice 16 adds.
- At 1024px and wider it has two panes. The left pane, 20rem wide, has the search field and the list. Each row shows the title, a kind tag, the chat title, the date in `num`, and the version count. The right pane shows the selected artifact. Its header has the title with rename, **Open in chat**, **Copy**, and **Download**. Under it is the versions list, then the preview.
- The preview reuses `ArtifactPanel`. Export it from `artifact-panel.tsx:78` and make `onFix` optional. With no composer on the page, **Fix** is hidden.
- Below 1024px the list fills the screen. A row opens the artifact full screen with a back button, and the versions row stays under the header at 360px and 390px.
- The selected artifact is in the URL as `/artifacts?id=<id>`, so a reload or a shared bookmark opens it.
- An empty page shows a hairline figure and no text beyond a short label.

## Rules

Do:

- Keep `extractArtifacts`, `artifactTitle`, `artifactFileName`, and `lineageFor` pure, and test them with hand-built inputs.
- Run the sync inside the message transaction, so a reply and its artifact rows are written together or not at all.
- Return `404` for another user's id, and add the three routes to slice 18's cross-user test.

Avoid:

- A second copy of the key format. Build keys with one `artifactKey(messageId, textOrdinal, blockIndex)` helper, and use it in `code-block.tsx` too.
- Rendering artifact code anywhere but the sandboxed frame or a code block.
- Re-parsing every message at every start. The backfill skips messages that already have rows.
