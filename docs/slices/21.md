# Slice 21. Artifacts page

Store every HTML, SVG, and React artifact the model writes, link versions across edits, regenerations, and branches, and give each user a private `/artifacts` library to search, rename, preview, compare versions, and download.

**Branch** `feat/artifacts-page`. **Depends on** [slice 16](16.md) (shipped in #273) for `ArtifactCard`, `artifactTitle`, `artifactFileName`, `ArtifactPanel`, and themed sandboxed previews, and [slice 18](18.md) (shipped in #279 and #281) for accounts, `instance_settings`, `src/lib/db/ownership.test.ts`, and `src/app/api/cross-user.test.ts`. Buildable directly on current `main` without [slice 19](19.md). Files ([slice 20](20.md)) and Share links ([slice 22](22.md)) stay out of scope.

## Why

An artifact exists today only while its message is mounted on screen. `CodeHeader` (`src/components/chat/code-block.tsx:63-66`) registers each HTML, SVG, JSX, or TSX block in a client `Map` inside `ArtifactProvider` (`src/components/artifacts/use-artifact.ts:23-39`). Nothing persists artifacts in SQLite.

Slice 16 already shipped `ArtifactCard` (`src/components/chat/artifact-card.tsx`), `artifactTitle` and `artifactFileName` (`src/lib/artifacts/title.ts`), syntax-highlighted code in `ArtifactPanel` (`src/components/artifacts/artifact-panel.tsx:86-104`), and title-derived download filenames (`artifact-panel.tsx:141-148`). Four gaps remain:

- To find last week's chart or interactive page, you have to remember the chat, scroll to the reply, and switch to the right branch.
- You cannot rename an artifact. Every card, panel header, and download stays fixed to the code-derived title.
- Regenerating a reply, editing a prompt, or asking for a follow-up change creates another artifact block with no link to earlier versions and no way to compare what changed between versions.
- Existing chats have no indexed artifact rows, so a new `/artifacts` page would open empty until backfilled.

Claude.ai users lost access to saved artifact versions when a menu item disappeared ([anthropics/claude-code#96718](https://github.com/anthropics/claude-code/issues/96718)). Orbit keeps the version list visible on screen whenever an artifact has more than one version.

## Scope

Ships:

- An `artifacts` table and an external-content `artifacts_fts` FTS5 index, updated atomically inside `finishChatReply` and `updateMessageText` in `src/lib/messages.ts`.
- Safe, idempotent startup backfill for existing chats, guarded by `instance_settings.artifacts_backfilled_at` and `withMigrationLock`.
- Deterministic version lineage across regenerations, prompt edits, follow-ups, and in-place reply or code edits.
- Inline rename for an entire lineage in both the chat `ArtifactPanel` and `/artifacts`, with redaction and reset to derived title on blank input.
- Downloads named from the shown title (user rename when set, else derived title).
- An always-visible `ArtifactVersions` strip (`v1`, `v2`, `v3`) and a **Diff** tab in `ArtifactPanel` to compare any two versions line by line, while switching versions on **Preview** compares live sandboxed renders.
- A private `/artifacts` page with full-text search, kind filter (**All**, **HTML**, **SVG**, **React**), pagination, sandboxed preview, version switcher, code diff, inline rename, download, and **Open in chat** landing on the exact branch and artifact.
- Navigation links in the sidebar, mobile drawer, command palette, and shell header title map, plus `/artifacts` frame-blocking headers in `next.config.ts`.

Does not ship:

- Deleting an individual artifact. Each artifact lives inside a saved assistant reply, and deleting it would mutate the message. Deleting the source chat or the user removes its artifact rows and FTS entries.
- File uploads, attachments, or `/files` ([slice 20](20.md)).
- Public or cross-user share links, or sharing an individual artifact ([slice 22](22.md)). Artifacts stay strictly private to their owner across Personal, Team, and Community modes.
- Artifacts inside the command palette search results. Search lives on `/artifacts`.
- Any changes to the preview iframe sandbox policy (`sandbox="allow-scripts"`) or CSP in `src/lib/artifacts/document.ts` and `src/components/artifacts/artifact-frame.tsx`.

### Storage and migrations

Edit `src/lib/db/schema.ts` to add one table (`artifacts`) and one nullable column on `instance_settings`.

New table `artifacts`:

| Column | SQLite type | Constraints and notes |
| --- | --- | --- |
| `seq` | `integer` | `PRIMARY KEY AUTOINCREMENT NOT NULL`. Stable rowid for `artifacts_fts` across `VACUUM` and deterministic tie-breaker for version ordering, matching `memories.seq` (`schema.ts:212`). |
| `id` | `text` | `NOT NULL UNIQUE`. UUID generated with `crypto.randomUUID()`. |
| `user_id` | `text` | `NOT NULL`, references `user.id` `ON DELETE CASCADE`. |
| `chat_id` | `text` | `NOT NULL`, references `chats.id` `ON DELETE CASCADE`. |
| `message_id` | `text` | `NOT NULL`, references `messages.id` `ON DELETE CASCADE`. |
| `text_ordinal` | `integer` | `NOT NULL`. 0-based index counting `text` parts only. `CHECK (text_ordinal >= 0)`. |
| `block_index` | `integer` | `NOT NULL`. 0-based index counting every mdast `code` node in that text part. `CHECK (block_index >= 0)`. |
| `kind` | `text` | `NOT NULL`, `"html" \| "svg" \| "react"`. |
| `language` | `text` | `NOT NULL`, `"html" \| "svg" \| "jsx" \| "tsx"`. |
| `code` | `text` | `NOT NULL`. Exact source matching `mdast-util-to-hast`. |
| `derived_title` | `text` | `NOT NULL`. Output of `artifactTitle({ kind, code })`. |
| `user_title` | `text` | Nullable. Written on every row of the lineage when renamed, and copied onto new versions joining the lineage. `NULL` falls back to `derived_title`. |
| `lineage_id` | `text` | `NOT NULL`. Equals `id` of the lineage's oldest row. |
| `created_at` | `integer` | `NOT NULL`, `timestamp_ms`. Copied from `messages.created_at` so versions sort in conversation order. |
| `updated_at` | `integer` | `NOT NULL`, `timestamp_ms`. Equals `created_at` on initial insert or backfill, and updates to `now` on in-place code edit. Rename leaves `updated_at` alone so list order stays stable. |

Table constraints and indexes on `artifacts`:

- `check("artifacts_slot_nonneg", sql`${table.textOrdinal} >= 0 AND ${table.blockIndex} >= 0`)`.
- `check("artifacts_kind_language", sql`(${table.kind} = 'html' AND ${table.language} = 'html') OR (${table.kind} = 'svg' AND ${table.language} = 'svg') OR (${table.kind} = 'react' AND ${table.language} IN ('jsx', 'tsx'))`)`.
- `uniqueIndex("artifacts_message_slot_idx").on(table.messageId, table.textOrdinal, table.blockIndex)`.
- `index("artifacts_user_updated_idx").on(table.userId, table.updatedAt, table.seq)`.
- `index("artifacts_user_lineage_idx").on(table.userId, table.lineageId, table.createdAt, table.seq)`.
- `index("artifacts_chat_idx").on(table.chatId)`.

Why `user_title` lives on every row in a lineage instead of only the root row:

- A user searching `"Tally Version 2"` matches `user_title` and the v2 `code` on the same row in `artifacts_fts`. Storing `user_title` only on the root row misses queries that combine a custom title with text introduced in a later version.
- `shownTitle(row)` reads `row.userTitle ?? row.derivedTitle` directly with no self-join to the root row.
- Promoting a new root after a block edit deletes the old root requires only updating `lineage_id`. Every surviving version already holds `user_title`.
- `renameArtifact` updates all rows with `WHERE user_id = ? AND lineage_id = ?` inside one SQLite transaction.

New column on `instance_settings`:

| Column | SQLite type | Constraints and notes |
| --- | --- | --- |
| `artifacts_backfilled_at` | `integer` | Nullable, `timestamp_ms`. `NULL` until startup backfill completes once. |

Required typecheck update for `instance_settings`:

- `src/lib/chat-errors.ts:11-39` enforces exhaustiveness over every column of `instanceSettings.$inferSelect` in `SETTINGS_FIELDS`. Add `artifactsBackfilledAt: "setting"` to `SETTINGS_FIELDS` so `npm run typecheck` passes. Do not add it to `PublicInstanceSettings` in `src/lib/instance-settings.ts`.

Custom FTS5 migration (`npx drizzle-kit generate --custom --name artifacts_fts`):

```sql
CREATE VIRTUAL TABLE artifacts_fts USING fts5(
	derived_title,
	user_title,
	code,
	content='artifacts',
	content_rowid='seq'
);
--> statement-breakpoint
CREATE TRIGGER artifacts_fts_ai AFTER INSERT ON artifacts BEGIN
	INSERT INTO artifacts_fts(rowid, derived_title, user_title, code)
	VALUES (new.seq, new.derived_title, new.user_title, new.code);
END;
--> statement-breakpoint
CREATE TRIGGER artifacts_fts_ad AFTER DELETE ON artifacts BEGIN
	INSERT INTO artifacts_fts(artifacts_fts, rowid, derived_title, user_title, code)
	VALUES ('delete', old.seq, old.derived_title, old.user_title, old.code);
END;
--> statement-breakpoint
CREATE TRIGGER artifacts_fts_au AFTER UPDATE OF derived_title, user_title, code ON artifacts BEGIN
	INSERT INTO artifacts_fts(artifacts_fts, rowid, derived_title, user_title, code)
	VALUES ('delete', old.seq, old.derived_title, old.user_title, old.code);
	INSERT INTO artifacts_fts(rowid, derived_title, user_title, code)
	VALUES (new.seq, new.derived_title, new.user_title, new.code);
END;
--> statement-breakpoint
INSERT INTO artifacts_fts(artifacts_fts) VALUES ('rebuild');
```

Verified against `better-sqlite3` 13.2.0 on this repo:

- `AFTER DELETE` triggers on `artifacts` fire on both explicit deletes and `ON DELETE CASCADE` from `chats`, `messages`, and `user`, even with default `recursive_triggers = 0`.
- Passing nullable `old.user_title` and `new.user_title` directly through `artifacts_fts_ai`, `artifacts_fts_au`, and `artifacts_fts_ad` passes `INSERT INTO artifacts_fts(artifacts_fts) VALUES ('integrity-check')` across `NULL` to string, string to `NULL`, and delete transitions.
- Using explicit `seq INTEGER PRIMARY KEY AUTOINCREMENT` with `content_rowid='seq'` preserves FTS rowid alignment across `VACUUM`.

Migration rules:

- Run `npm run db:generate -- --name artifacts` for the schema migration, then `npx drizzle-kit generate --custom --name artifacts_fts` for the FTS5 table and triggers.
- Never hard-code a migration sequence number in code, tests, or docs. Discover the Slice 21 migrations dynamically from `drizzle/meta/_journal.json` by tag suffix (`_artifacts` and `_artifacts_fts`), so the suite survives rebasing after [slice 19](19.md) lands.

### Finding artifacts in a reply

`extractArtifacts(parts)` in `src/lib/artifacts/extract.ts` is a pure function.

```ts
export type ExtractedArtifact = {
	textOrdinal: number;
	blockIndex: number;
	artifactPosition: number; // 0-based index counting artifact blocks only across the message
	kind: ArtifactKind;
	language: ArtifactLanguage;
	code: string;
	derivedTitle: string;
};

export function extractArtifacts(parts: unknown): ExtractedArtifact[];
```

Rules, verified against `react-markdown` 10.1.0, `mdast-util-to-hast` (`lib/handlers/code.js`), `@assistant-ui/react-markdown` 0.14.26 (`code-fence.js`, `CodeOverride.js`), and `src/lib/markdown-code.ts`:

1. Return `[]` when `parts` is not an array.
2. Walk `parts` in order. Only elements with `part.type === "text"` and `typeof part.text === "string"` increment `textOrdinal` (starting at `0`). This matches `src/components/chat/markdown-text.tsx:94-98` and excludes `reasoning`, `tool-*`, `step-start`, and `data-*` parts.
3. Parse each text part with `unified().use(remarkParse).use(remarkGfm).parse(part.text)`, matching `remarkGfm` in `src/components/chat/markdown-text.tsx:86`. `unified` `11.0.5` and `remark-parse` `11.0.0` are already in `node_modules`. Add both to `dependencies` in `package.json` at those exact versions. Walk the mdast tree with a small local depth-first function instead of adding another dependency.
4. Increment `blockIndex` (starting at `0` per text part) on every mdast `code` node in document order, including indented code blocks, unlabeled blocks, Python blocks, and code blocks nested inside blockquotes or lists. This matches `rehypeCodeBlocks` (`src/lib/markdown-code.ts:8-23`), which numbers every `<pre>` containing a `<code>` element.
5. Extract the language token with `const rawLang = typeof node.lang === "string" ? node.lang.split(/\s+/)[0] : ""` (matching `mdast-util-to-hast/lib/handlers/code.js`), without lowercasing (matching `parseLanguageClass` in `@assistant-ui/react-markdown` and `isArtifactLanguage` in `src/lib/artifacts/detect.ts:11-13`). Keep only nodes where `isArtifactLanguage(rawLang)` is true.
6. Set `code = node.value ? `${node.value}\n` : ""`. `mdast-util-to-hast` appends `"\n"` to every non-empty code block and keeps `""` empty. Matching this byte for byte guarantees that Copy, Download, and Diff on `/artifacts` produce the exact same bytes as `CodeHeader` and `ArtifactPanel` in the chat.
7. Set `kind = artifactKind(rawLang)!`, `derivedTitle = artifactTitle({ kind, code })`, and `artifactPosition` sequentially from `0` across all extracted artifacts in the message.

### Artifact identity and version lineage

Every artifact has two stable identifiers:

- **Block slot `(message_id, text_ordinal, block_index)` and key `artifactKey(messageId, textOrdinal, blockIndex)`.** Maps 1:1 to a rendered `ArtifactCard` and to `?artifact=<key>` URLs (`src/lib/artifacts/history.ts:5-13`).
- **Row UUID `id` and lineage UUID `lineage_id`.** `id` identifies one version across API routes and `/artifacts?id=<id>` bookmarks. `lineage_id` links related versions across regenerations, prompt edits, and follow-up turns in the same chat.

`lineageFor(candidate, tree, earlier, claimedLineageIds)` in `src/lib/artifacts/lineage.ts` is a pure function.

```ts
export type MessageNode = {
	id: string;
	parentId: string | null;
	role: "user" | "assistant" | "system";
	createdAt: number;
};

export type ExistingArtifact = {
	id: string;
	messageId: string;
	textOrdinal: number;
	blockIndex: number;
	artifactPosition: number;
	kind: ArtifactKind;
	derivedTitle: string;
	userTitle: string | null;
	lineageId: string;
	createdAt: number;
	seq: number;
};

export type ArtifactCandidate = {
	messageId: string;
	textOrdinal: number;
	blockIndex: number;
	artifactPosition: number;
	kind: ArtifactKind;
	derivedTitle: string;
};

export type LineageMatch =
	| { kind: "join"; lineageId: string; userTitle: string | null }
	| { kind: "new" };

export function lineageFor(
	candidate: ArtifactCandidate,
	tree: readonly MessageNode[],
	earlier: readonly ExistingArtifact[],
	claimedLineageIds?: ReadonlySet<string>,
): LineageMatch;
```

Let `M` be the assistant message matching `candidate.messageId`, `P` be `M.parentId` (the prompt), and `G` be `P.parentId` (`string | null`). If `M` or `P` is missing from `tree`, return `{ kind: "new" }`. Compute three message sets from `tree`:

- `siblingReplies` holds assistant messages with `id !== M.id` and `parentId === P.id` (regenerations of `P`).
- `editedPromptReplies` holds assistant messages with `id !== M.id` whose parent `U` has `role === "user"`, `U.id !== P.id`, and `U.parentId === G` (replies to edited versions of `P`, including when `G === null` for edits of the first prompt).
- `ancestorReplies` holds assistant messages on `pathTo(tree, G)` (prior turns on the current branch leading to `P`). Replies on unrelated sibling subtrees that diverged earlier are excluded, so independent branches do not merge.

Filter `earlier` to rows with `row.kind === candidate.kind`, `row.messageId !== candidate.messageId`, and `!claimedLineageIds?.has(row.lineageId)` (preventing two blocks in the same reply from collapsing into one lineage). Evaluate rules in order:

1. **Same non-fallback title among relatives** (`siblingReplies ∪ editedPromptReplies ∪ ancestorReplies`).
   - Skip this rule if `candidate.derivedTitle === FALLBACK_TITLE[candidate.kind]` (`"HTML page"`, `"SVG image"`, or `"React component"`). Two unrelated untitled follow-up artifacts in the same chat must not merge on a generic fallback title.
   - Normalize titles with `value.trim().toLowerCase()`. Find all matching relatives whose normalized `derivedTitle` or normalized `userTitle` equals the candidate's normalized `derivedTitle`.
   - Join the newest match by `(createdAt DESC, seq DESC)`. This covers follow-ups like "make the button blue" when `<title>` stays `"Counter"`, follow-ups that adopt the user's renamed title, and regenerations that reorder multiple artifacts in one reply.
2. **Same artifact position among regenerations and edited prompts** (`siblingReplies ∪ editedPromptReplies`).
   - Among messages in `siblingReplies ∪ editedPromptReplies` that have at least one artifact in `earlier`, pick the most recent message `R` by `(R.createdAt DESC, maxRowSeq DESC)`.
   - Look for an eligible artifact in `R` with the same `kind` and the same `artifactPosition` (counting artifacts only, ignoring Python or plain code blocks).
   - If found, join its lineage. This links regenerations and prompt edits even when the model changes `<title>` or emits an anonymous component with a fallback title.
3. **New lineage.** Otherwise return `{ kind: "new" }`. The inserted row sets `lineage_id = id` and `user_title = null`.

Version numbering and ordering:

- Versions in a lineage sort oldest-first by `(created_at ASC, seq ASC)`.
- Version `number` is the 1-based rank (`1`, `2`, `3`, shown as `v1`, `v2`, `v3`).
- An in-place edit updates `code`, `derived_title`, and `updated_at` on the same row and keeps `created_at` and `seq`, so version numbers do not shift.

### Comparing versions

Users compare versions in two complementary ways inside the same `ArtifactPanel`:

- **Live preview comparison.** When a lineage has more than one version (`versions.length > 1`), `ArtifactVersions` stays visible directly under the panel header. Clicking `v1`, `v2`, `v3` while on **Preview** swaps the live sandboxed render immediately.
- **Line-by-line code diff.** When `versions.length > 1`, `ArtifactPanel` adds a **Diff** tab after **Preview** and **Code**. Single-version artifacts show only **Preview** and **Code**, preserving existing keyboard-tab behavior in `scenarios/artifact-review.mjs:122-135`.

`diffArtifactLines(before, after)` in `src/lib/artifacts/diff.ts` is a pure function with zero external dependencies:

```ts
export type DiffLine =
	| { kind: "context"; beforeLine: number; afterLine: number; text: string }
	| { kind: "removed"; beforeLine: number; afterLine: null; text: string }
	| { kind: "added"; beforeLine: null; afterLine: number; text: string };

export type DiffHunk =
	| { kind: "changes"; lines: DiffLine[] }
	| { kind: "collapsed"; lines: Extract<DiffLine, { kind: "context" }>[] };

export type ArtifactDiff =
	| { status: "identical" }
	| { status: "too-large"; beforeLines: number; afterLines: number }
	| { status: "ready"; added: number; removed: number; hunks: DiffHunk[] };

export function diffArtifactLines(before: string, after: string): ArtifactDiff;
```

Diff behavior:

- Normalize line endings (`\r\n` and `\r` to `\n`) before splitting so CRLF vs LF changes do not mark the whole file changed.
- Return `{ status: "identical" }` when normalized strings match.
- Trim identical leading and trailing lines first, then run an exact LCS diff on the changed middle slice. If the trimmed middle exceeds `2_000_000` DP cells or either side exceeds `4_000` trimmed lines, return `{ status: "too-large", beforeLines, afterLines }` so a giant minified SVG cannot freeze the browser.
- Collapse runs of more than 6 unchanged lines into `{ kind: "collapsed", lines }`, keeping 3 lines of context before and after every change. Clicking a collapsed bar expands those lines in place.
- **Default base version for Diff.** When viewing `vN` (`N > 1`), default to `v(N - 1)`. When viewing `v1`, default to `v2` so opening **Diff** shows a real comparison right away. A compact `<Select>` (`src/components/ui/select.tsx`) lets the user switch the base version to any other version in the lineage, next to `+added` (`text-positive num`) and `-removed` (`text-destructive num`) counts.
- Fetch the base version's `code` on demand through `GET /api/artifacts/[baseId]` via `requestJson` and cache it in a client `Map<string, string>` keyed by `${id}:${updatedAt}`. That keeps initial SSR and list payloads small and lets **Diff** work across branches inside the chat panel as well as on `/artifacts`.
- Render diff lines as plain React text inside `bg-surface-sunken font-mono text-code` wrapped in `ScrollFade axis="x" fade="var(--surface-sunken)"` (unified layout, never side-by-side split columns, so `360px` and `390px` phones stay readable with zero page overflow). Added lines use `bg-positive/12` with `+` in `text-positive`. Removed lines use `bg-destructive/12` with `-` in `text-destructive`.

### When rows are written

`syncMessageArtifacts(userId, chatId, messageId, parts, messageCreatedAt, db, options?)` in `src/lib/artifacts/store.ts` runs synchronously inside the existing SQLite message write transactions.

Write paths:

1. **`finishChatReply` (`src/lib/messages.ts:339-350`).**
   - Covers new replies, regenerations, continued replies (`plan.continues !== null`), and stopped or failed replies that still have visible text.
   - Always pass the already-redacted parts returned by `messageBody(parts, redact)` so no credential stripped from `messages.parts` can enter `artifacts.code`, `artifacts.derived_title`, or `artifacts_fts`.
   - When `insertMessage` succeeds (new reply) or the `plan.continues` update runs, look up `chats.userId` and the stored message's `createdAt` inside the same `db.transaction` and call `syncMessageArtifacts`.
   - `finishChatReply` is hashed in `docs/architecture/model-sync.json`. Follow `.agents/skills/verify-chat-turn/SKILL.md`, run `scripts/ci/tlc.sh`, confirm all pass configs pass and all mutant traces still match, and update `"src/lib/messages.ts finishChatReply"`.
2. **`updateMessageText` (`src/lib/messages.ts:352-369`).**

   - Today `updateMessageText` does not use a transaction. Wrap its message select, `db.update(messages)`, and `syncMessageArtifacts` in one `db.transaction(...)` so the message edit and artifact rows commit atomically.
   - Pass the already-redacted parts from `messageBody(parts, redact)`.
   - `updateMessageText` is also hashed in `docs/architecture/model-sync.json`. Verify with `scripts/ci/tlc.sh` and update `"src/lib/messages.ts updateMessageText"`.
3. **Nothing writes while streaming.**
   - During streaming, `CodeHeader` renders the Slice 16 busy `ArtifactCard` with **Open** disabled and registers the live block in `ArtifactProvider`.
   - When the stream ends, `finishChatReply` commits the message and artifacts together, `ReplyLink.finish` calls `router.refresh()` (`src/components/chat/chat-panel.tsx:64-76`), and `ChatPage` passes the updated `initialArtifacts` map into `ChatPanel`.
   - After an in-place edit succeeds in `useSaveMessageText` (`src/components/chat/use-save-message.ts`), call `artifacts?.refresh()` so `ArtifactProvider` fetches fresh metadata from `GET /api/chats/[id]/artifacts` without disturbing the active branch in `ChatPanel`.

Reconciliation rules inside `syncMessageArtifacts`:

1. Extract blocks from `parts` with `extractArtifacts(parts)`. Load existing rows for `(userId, messageId)`. If both are empty, return immediately with zero writes.
2. **Exact slot matches.** For every extracted block whose `(textOrdinal, blockIndex)` matches an existing row of the same `kind`, update `language`, `code`, `derived_title`, and `updated_at = now` only if `language`, `code`, or `derived_title` changed. If identical, write nothing (idempotent). Keep `id`, `seq`, `lineage_id`, `user_title`, and `created_at`.
3. **Shifted block matches (block added or removed above an existing block).** For remaining unmatched extracted blocks and unmatched old rows of the same `messageId`, pair any unmatched old row that has the exact same `kind` and `code`. Reassign their `(text_ordinal, block_index)` in two steps (first move to temporary `block_index = 1_000_000 + i`, then move to final `(textOrdinal, blockIndex)`) so the unique slot index never collides and `artifacts_fts_au` does not fire unnecessarily. This preserves `id`, `lineage_id`, `user_title`, and `/artifacts?id=<id>` bookmarks when an edit inserts a Python block above an HTML block.
4. **Removed blocks and root promotion.** Delete remaining unmatched old rows (including a slot whose `kind` changed, such as `html` edited to `svg`). For each deleted row where `row.id === row.lineageId`, query the oldest remaining row in that lineage (`WHERE user_id = ? AND lineage_id = ? ORDER BY created_at ASC, seq ASC LIMIT 1`). If one exists, promote it by running `UPDATE artifacts SET lineage_id = ? WHERE user_id = ? AND lineage_id = ?`. Because `user_title` lives on every row in the lineage, renames survive root deletion.
5. **New blocks.** For remaining unmatched extracted blocks (in order), load the chat's message tree and existing chat artifacts once, call `lineageFor`, and insert each new row (`created_at = messageCreatedAt`, `updated_at = options?.backfill ? messageCreatedAt : now`). Track `claimedLineageIds` across blocks inserted for the same message.

Running `syncMessageArtifacts` twice with the same parts produces zero writes.

### Safe backfill on repeated boots

`backfillArtifacts(options?)` in `src/lib/artifacts/backfill.ts` runs once at server start from `src/instrumentation.ts` (under `process.env.NEXT_RUNTIME === "nodejs"`), right after `getInstance()` opens SQLite, runs Drizzle migrations, and seeds `instance_settings`.

```ts
export type BackfillResult = {
	skipped: boolean;
	scannedMessages: number;
	insertedRows: number;
	skippedCorrupt: number;
	durationMs: number;
};

export function backfillArtifacts(options?: { batchSize?: number; lockDir?: string }): BackfillResult;
```

Boot safety and idempotency guarantees:

1. **Fast path on repeated boots.** Check `SELECT artifacts_backfilled_at FROM instance_settings WHERE id = 1` first. When non-null, return immediately with `{ skipped: true, scannedMessages: 0, insertedRows: 0, skippedCorrupt: 0, durationMs: 0 }`. Zero locks acquired and zero messages read.
2. **Cross-process lock.** When `artifacts_backfilled_at` is null, acquire `withMigrationLock` (`src/lib/db/migration-lock.ts`) on `options?.lockDir ?? dataDirectory()` and re-check `artifacts_backfilled_at` inside the lock so two concurrent boots never duplicate work.
3. **Candidate selection.** Select assistant messages with a fence marker using SQLite `instr` (avoiding `LIKE` escape quirks):
   ```sql
   SELECT messages.id, messages.chat_id AS chatId, chats.user_id AS userId,
          messages.parts, messages.created_at AS createdAt
   FROM messages
   JOIN chats ON chats.id = messages.chat_id
   WHERE messages.role = 'assistant'
     AND (instr(messages.content, '```') > 0 OR instr(messages.content, '~~~') > 0)
   ORDER BY chats.id ASC, messages.created_at ASC, messages.rowid ASC
   ```
   Every CommonMark artifact block requires a backtick or tilde fence (indented blocks carry no language tag and cannot pass `isArtifactLanguage`). This catches `` ```html ``, `` ``` html `` (space before tag), `` ````html ``, and `~~~svg`, while skipping plain prose replies.
4. **Chronological lineage order and batching.** Grouping by `chats.id ASC` and ordering each chat's messages by `created_at ASC, rowid ASC` ensures `lineageFor` sees earlier versions before regenerations, prompt edits, and follow-ups. Commit in transactions of at most `200` messages (configurable via `batchSize` for tests).
5. **Corrupt JSON tolerance.** Parse each `messages.parts` inside `try` and `catch`. If a legacy row holds invalid JSON, increment `skippedCorrupt`, log one summary warning containing only the count (never message content), and continue so one corrupt row cannot block server startup.
6. **Crash recovery.** `instance_settings.artifacts_backfilled_at` is set to `new Date()` ONLY after the final batch commits. If the server crashes or receives `SIGKILL` mid-pass, `artifacts_backfilled_at` remains `NULL`, and the next boot reruns the pass. Because `syncMessageArtifacts` is a no-op on already-synced messages (preserving existing `id`, `lineage_id`, `user_title`, and timestamps), rerunning converges to the exact same database state with zero duplicate rows.
7. **Fresh installs.** On a new database with zero assistant messages, the first boot scans 0 messages, inserts 0 rows, stamps `artifacts_backfilled_at`, and every later boot hits the fast path.

### Rebasing and regenerating migrations after Slice 19 lands

Follow these exact steps if Slice 19 merges into `main` before `feat/artifacts-page` merges:

1. Run `git fetch origin && git rebase origin/main` and resolve any conflicts in the shared files above.
2. Do not hand-edit `drizzle/meta/_journal.json` or snapshot `prevId` fields. Reset `drizzle/` to `origin/main` first with `git checkout origin/main -- drizzle/`.
3. Regenerate the schema migration on top of Slice 19's snapshot with `npm run db:generate -- --name artifacts`.
4. Regenerate the FTS5 custom migration with `npx drizzle-kit generate --custom --name artifacts_fts`, then paste the `artifacts_fts` virtual table, triggers, and `rebuild` SQL into the newly generated SQL file.
5. Verify that `src/lib/db/artifacts-migration.test.ts` still discovers the two migrations dynamically by tag suffix (`_artifacts`, `_artifacts_fts`) with no hard-coded index.
6. Run `scripts/ci/tlc.sh`, `npm test`, `npm run typecheck`, `npm run lint`, and `npm run build` before pushing.

## Rules

Do:

- Keep `extractArtifacts`, `artifactKey`, `artifactTitle`, `shownTitle`, `artifactFileName`, `lineageFor`, and `diffArtifactLines` pure and test them with hand-built inputs.
- Pass already-redacted message parts into `syncMessageArtifacts` inside the same SQLite transaction as the message write.
- Pass `userId: UserId` as the first argument to every `src/lib/artifacts/store.ts` helper and return `404` for another user's id.
- Build all route schemas with `r` and `LIMITS` from `src/lib/route-schema.ts`, and send all browser requests through `requestJson` or `useLoaded` from `src/lib/request-json.ts`.
- Run `scripts/ci/tlc.sh` and update `docs/architecture/model-sync.json` after editing `finishChatReply` and `updateMessageText`.
- Wait for async UI or server state in tests and scenarios with `eventually` from `src/lib/eventually.mjs`, never fixed sleeps (`src/lib/no-fixed-waits.test.ts`).
- Rely on `scripts/test-data-dir.mjs` for test database isolation. Never set `ORBIT_DATA_DIR` inside test files, and run one file with `node --import tsx --import ./scripts/test-data-dir.mjs --test <file>`.

Avoid:

- A second copy of the `` `${messageId}.${textOrdinal}.${blockIndex}` `` key format. Use `artifactKey` everywhere.
- Rendering artifact code outside `ArtifactFrame` or plain React text nodes.
- Passing a `Map` across the Next.js Server Component to Client Component boundary. Use plain objects (`Record<string, StoredChatArtifact>`).
- Hard-coding a Drizzle migration number in code, tests, or docs.
- Re-parsing assistant messages on startup after `instance_settings.artifacts_backfilled_at` is set.
- Letting generic fallback titles (`"HTML page"`, `"SVG image"`, `"React component"`) merge unrelated follow-up artifacts into one lineage.
- Adding Files ([slice 20](20.md)), Share links ([slice 22](22.md)), new CSS tokens, or helper copy.
