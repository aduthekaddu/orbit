# Slice 22. Share links

Publish a read-only copy of the branch you are looking at, at a long random link. Before anything goes public you see exactly what will be shown. You can update the link, revoke it, or let it expire.

**Branch** `feat/share-links`. **Depends on** [slice 18](18.md) for accounts and the cross-user route test, [slice 20](20.md) for the chat toolbar in `chat-actions.tsx` and the file parts its proof checks, and the `artifacts` table from [slice 21](21.md).

## Why

You cannot show someone an Orbit conversation today except with a screenshot. Every page needs a session (`src/proxy.ts:24-26`), and behind Cloudflare Access every request also needs an allowed email.

Sharing is where competing apps leaked. Open WebUI let a `javascript:` link in a shared chat's citation steal the viewer's session (GHSA-qpqv-xwg8-cqpj). It ran a shared chat's code on the server (GHSA-4r2p-27mh-5m22), and a shared branch ignored access checks and allowed file deletion (GHSA-26g9-27vm-x3q8). ChatGPT's "make this chat discoverable" put private chats in search results until OpenAI removed it. Claude.ai warns that a shared artifact exposes the chat's attachments. None of the apps compared shows a preview of what will become public. The research is in the v1 plan, step 8, and its benchmarks file.

## Scope

Ships:

- A `shares` table. A share is a frozen snapshot of one branch of one chat, at an unguessable token.
- A share dialog with a preview of exactly what becomes public and a short list of what is left out.
- **Create link**, **Update link** to republish to the same URL, **Revoke**, and an expiry of Never, 1 day, 7 days, or 30 days.
- A **Shared links** list in Settings.
- A public page at `/s/<token>`, with `noindex`, a strict CSP, and artifacts in the sandboxed frame.
- The `src/proxy.ts` change and the Cloudflare Access bypass, documented in the README.

Does not ship:

- Files, reasoning, memory notes, or raw tool input and output. They are left out of every share.
- Continue this chat, comments, view counts, or a share that updates by itself.
- Sharing a single artifact on its own.
- More than one link per chat. **Update link** moves the one link to the branch you are viewing.

## Design

### Data shape

```ts
type SharePart =
	| { type: "text"; text: string } // markdown for the assistant, plain text for the user
	| { type: "widget"; spec: Spec } // a render_ui spec that passed parseRenderSpec again
	| { type: "tool"; label: string; outcome: "succeeded" | "failed" | "cancelled" }
	| { type: "file" }; // a marker only, with no name, type, or size

type ShareMessage = { id: string; role: "user" | "assistant"; parts: SharePart[] }; // ids are "m0", "m1", ...

type ShareSnapshot = {
	version: 1;
	title: string;
	messages: ShareMessage[];
	artifacts: { key: string; title: string }[]; // key is `${shareMessageId}.${textOrdinal}.${blockIndex}`
};

type LeftOut = { files: number; reasoning: number; toolDetails: number };

type ShareExpiry = "never" | "1d" | "7d" | "30d";
```

`shares` in `src/lib/db/schema.ts`:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | text primary key | UUID |
| `user_id` | text not null | references `user.id` on delete cascade |
| `chat_id` | text not null unique | references `chats.id` on delete cascade. One link per chat. |
| `token` | text not null unique | 32 random bytes from `crypto.randomBytes`, base64url, 43 characters |
| `title` | text not null | copied from the snapshot for the list |
| `snapshot` | text not null | `ShareSnapshot` as JSON, at most 5 MB |
| `created_at`, `updated_at` | integer not null | `timestamp_ms` |
| `expires_at` | integer | null means never |

The token is stored as is. The owner needs to copy the link again from the list, and anyone who can read the database can already read the chat. Lookups compare the whole token with `eq`, never `LIKE` (Open WebUI GHSA-wpmr-8h3q-fwj7). The public route checks the token's shape with zod before it queries.

### What a snapshot keeps

`buildShareSnapshot(path, artifacts)` in `src/lib/share/snapshot.ts` is a pure function. It takes the stored messages on the chosen path and the chat's artifact rows, and returns `{ snapshot, leftOut }`. It copies only parts it knows. Everything else is dropped. A new part type stays private until someone adds it here on purpose.

| Stored part | In the share | Counted in `leftOut` |
| --- | --- | --- |
| `text` | as is | |
| `tool-render_ui` with a valid spec | `widget` | |
| any other `tool-*`, including `github_*`, `remember`, `forget`, `web_search`, `run_code` | `tool` with a label and outcome only | `toolDetails` |
| `file` (slice 20) | `file` marker | `files` |
| `reasoning` | dropped | `reasoning` |
| `step-start`, `source-*`, `data-*`, anything else | dropped | |

- The tool label comes from slice 15's plain tool names, and the outcome from `toolRunStatus` (`src/lib/tools/run-status.ts:10`). Search queries, code, code output, GitHub results, and the text of a saved memory are tool input or output, so none of them reach the share.
- Memory notes are not stored in messages. `attachMemoryNotes` adds them to the model request only (`src/lib/memory/recall.ts:28-37`). A reply can still repeat a memory in its own words. The preview shows that text, so you can see it before publishing.
- Message ids become `m0`, `m1`, and so on, so internal ids stay private. Text is unchanged, and `textOrdinal` counts text parts only, so an artifact key keeps its `textOrdinal` and `blockIndex` under the new message id. The `artifacts` list takes each title from slice 21's table.
- The chat title is copied as it is.

### Choosing the branch

The open branch is not always `chats.head_id`, because switching branches does not update it (`ARCHITECTURE.md`, History). The dialog sends `leafId`, the last message of the branch on screen. The route checks that the chat is yours and that `leafId` is one of its messages. Otherwise it returns `404`. Then it takes the path with `pathTo` (`src/lib/chat-tree.ts:5`) over `messageRepository(chatId)` (`src/lib/messages.ts:246-249`).

### Flow

1. **Share** in the chat toolbar from slice 20 (`src/components/chat/chat-actions.tsx`) opens the dialog. It is a centered dialog on desktop and a bottom sheet on a phone.
2. The dialog calls `POST /api/chats/[id]/share/preview` with `{ leafId }`. Nothing is written. The response is `{ snapshot, leftOut, previewHash, share }`, where `share` is the current link or null. `previewHash` is the SHA-256 hex of the snapshot's JSON, from `shareHash(snapshot)` in `snapshot.ts`. `buildShareSnapshot` emits keys in a fixed order, so the same messages always give the same hash.
3. The dialog renders the snapshot with `SharedThread`, the same component the public page uses, in a scrolling well. Above it, one line lists what is left out, such as "Not shared: 2 files, reasoning, 3 tool details". A zero count is not shown.
4. Pick an expiry, then **Create link**, or **Update link** when a link exists. Both call `PUT /api/chats/[id]/share` with `{ leafId, expiry, previewHash }`. The server builds the snapshot again from the database, not from the client. If `shareHash` of the new snapshot differs from `previewHash`, it writes nothing and answers 409 with the new `{ snapshot, leftOut, previewHash }`. The dialog shows that preview in place of the old one with the line `Preview changed`, and the person presses the button again. Otherwise it upserts on `chat_id`, and an update keeps the token. Between the preview and the press, another tab can edit a reply in place (`updateMessageText`, `src/lib/messages.ts:214-229`), rename the chat, or rename an artifact. Without the hash the link would publish text the person never saw.
5. The dialog shows the link with **Copy**, and **Revoke**. **Revoke** calls `DELETE /api/chats/[id]/share`, which deletes the row. The link then returns `404`.

`GET /api/shares` lists your links for the **Shared links** section in Settings (`src/app/(app)/settings/page.tsx`). Each row has the title, the updated date, the expiry or "Expired", **Copy**, **Open chat**, and **Revoke**. If slice 18 split Settings into instance and personal parts, the list goes in the personal part.

Every helper in `src/lib/share/store.ts` takes `userId` first: `previewShare(userId, chatId, leafId)`, `publishShare(userId, chatId, leafId, expiry, previewHash)`, which returns `{ kind: "published"; share } | { kind: "changed"; preview }`,, `revokeShare(userId, chatId)`, `listShares(userId)`. One function reads a share without a user, `shareByToken(token, now)`. It returns null for an unknown, revoked, or expired token, and only the public page and frame route call it.

The link is `<base>/s/<token>`. The base comes from `resolveAuthBaseUrl` (`src/lib/auth-origins.ts:9-10`), which reads `ORBIT_PUBLIC_URL` and then `BETTER_AUTH_URL`.

Whether members of a `team` or `community` install may make public links is a maintainer decision. Until it is made, sharing is on in every mode. The `PUT` route is the one place a `policyFor(mode)` check would go.

### The public page

`src/app/s/[token]/page.tsx` sits outside the `(app)` group, so it never renders the app shell or the owner's chat list (`src/app/(app)/layout.tsx`). It is server-rendered with `dynamic = "force-dynamic"` and passes the snapshot to a client `SharedThread`.

`SharedThread` reuses the chat's rendering so a share looks like the chat. Artifact cards open in this read-only view because slice 16 removes the edit check from **Open** (`src/components/chat/code-block.tsx:77` disables it today whenever editing is off). `MarkdownText` calls `useAISDKChat()`, which returns `undefined` outside the AI SDK runtime, so it renders without a chat. It wraps the snapshot in a read-only `useExternalStoreRuntime` from `@assistant-ui/react` and renders read-only versions of the user and assistant messages from `src/components/chat/messages.tsx`, with no composer, edit, regenerate, copy-to-composer, or branch picker. Text goes through `MarkdownText` with `editable` false. Widgets go through the slice 15 widget renderer with a `readOnly` flag, passed through a small context next to the registry in `src/components/genui/registry.tsx`. Read-only `Text` renders its content as a React text child in a plain element, with no `contentEditable`, no pencil, and no `dangerouslySetInnerHTML`. Today's `EditableText` sets escaped model text through `dangerouslySetInnerHTML` on a `contentEditable` element (`registry.tsx:87-115`). The escape makes that safe in the chat, but the contract keeps model text out of `dangerouslySetInnerHTML`, and a public page should not offer a text box a viewer can type into. `Button` keeps working, because it only shows its note on the page. `tool` and `file` parts become `data-share-tool` and `data-share-file` parts with small components. Two things are inferred and need checking in turn 1. One is whether assistant-ui 0.15.32 renders `data-*` parts through `MessagePrimitive.Parts` with an external store. The other is whether `MarkdownText` works outside the AI SDK runtime, since it calls `useAISDKChat()` (`src/components/chat/markdown-text.tsx:80`). If either fails, give `MarkdownText` an optional source hook and render the two marker parts outside the markdown.

Layout:

- One column at `max-w-chat` from slice 14. A header with the chat title, clamped to two lines, and the updated date in `num`. No sidebar, no account menu, and no taglines.
- At 360px and 390px, user bubbles keep the 85% width, widgets and code scroll inside `ScrollFade`, and the page does not scroll sideways. An artifact opens full screen, as `ArtifactWorkspace` does below 1024px (`src/components/artifacts/artifact-panel.tsx:59-71`).
- A `file` marker is a small bordered chip that says "File not shared". A `tool` part is one line with the label and outcome, in the collapsed style from slice 15.

### Headers and CSP

`src/proxy.ts` makes `/s/` public. Today `PUBLIC_PAGES` holds exact paths only (`src/proxy.ts:4`), and a signed-in visitor to a public page is redirected to `/` (`src/proxy.ts:27-29`). Add a prefix check for `/s/` before the session lookup that returns early for any visitor. If slice 18 already added a prefix list for `/invite/`, add `/s/` to it. `startsWith("/s/")` does not match `/settings`.

For `/s/` page requests the proxy also sets:

- `Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-<n>' 'strict-dynamic'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; frame-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'; object-src 'none'`, with a fresh nonce per request. It also passes the policy on the request headers, which is how Next applies the nonce to its own scripts. That last point is from the Next docs and is not yet tried on Next 16.4.3. Turn 1 checks the console for CSP errors. `img-src 'self'` blocks remote images in model text, so a share cannot carry a tracking pixel.
- `X-Robots-Tag: noindex, nofollow`, plus `robots: { index: false, follow: false }` in the page metadata.
- `Referrer-Policy: no-referrer`, so the token never leaves in a `Referer` header when a viewer clicks a link.
- `Cache-Control: no-store`, so a revoked link stops working at once, also through Cloudflare.

Artifacts cannot use `srcDoc` here. An `about:srcdoc` frame inherits its parent's CSP. The page's nonce policy would then block the artifact's inline scripts, which `src/lib/artifacts/document.ts:4` allows. Instead the frame loads `/s/<token>/frame/<n>`, where `n` is the artifact's index in `snapshot.artifacts`. The URL ends in a number, never in a file extension.

`src/app/s/[token]/frame/[n]/route.ts`:

- Finds the share with `shareByToken`, finds the block with `extractArtifacts` from slice 21 on the snapshot message, and builds the document with `artifactDocument` (`document.ts:17-45`). The JSX step the panel runs in the browser today (`artifact-panel.tsx:93-96`) moves into a shared `artifactSource(kind, code)` helper in `document.ts`, so the panel and this route prepare code the same way.
- Responds with `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline' https://esm.sh; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; connect-src 'none'`. The `sandbox` directive matters. Someone could open the frame URL directly as a top-level page. Without it, model-written HTML would then run on Orbit's origin with the viewer's cookies.
- Also sends `X-Content-Type-Options: nosniff`, `X-Robots-Tag: noindex`, and `Cache-Control: no-store`.
- Answers 404 unless the request has `Sec-Fetch-Dest: iframe`, and adds `frame-ancestors 'self'` to its CSP. A person who opens the frame URL in a tab, or another site that embeds it, gets nothing, so model-written HTML never shows as a page of its own at an Orbit URL. A test sends the request with and without the header.

`ArtifactFrame` (`src/components/artifacts/artifact-frame.tsx:28`) takes either `document` for `srcDoc` or `src` for a URL. The `sandbox="allow-scripts"` attribute stays in both cases.

Markdown links keep react-markdown's default URL check, which drops `javascript:` links. A test feeds `[x](javascript:alert(1))` and `[x](JAVASCRIPT:alert(1))` through `SharedThread` and checks that neither renders an `href`.

### Cloudflare Access

Behind Access, a viewer without an allowed email never reaches Orbit. Add to **Deploy behind Cloudflare** in `README.md` (`README.md:146`):

- A second Access application, or more paths on the first, for `<host>/s/` and `<host>/_next/static/`, with one policy whose action is **Bypass** for Everyone. The page needs its scripts, styles, and fonts, which are served from `/_next/static/`. Those are public build output and hold no secrets.
- A check. `curl -sS -o /dev/null -w '%{http_code}\n' https://orbit.example.com/s/<token>` answers `200`, and `https://orbit.example.com/` still answers `302` to `cloudflareaccess.com`.
- A note that without Access, `src/proxy.ts` is the only gate, and the 256-bit token is what keeps a link private.

Update the **Cloudflare Access** section of `SECURITY.md` (`SECURITY.md:32-44`). It says every page sits behind Access, and that stops being true. Note that a later check of the Access JWT must skip `/s/`.

### Deleting

- Deleting a chat cascades its share through `chat_id`, and the link returns `404`.
- Deleting a user cascades through `user_id`.
- Editing or regenerating messages does not change a share until you press **Update link**.
- Deleting a file in slice 20 changes nothing, because shares never hold files.
- Unknown, revoked, and expired tokens all return the same `404` page, so a link does not show whether it ever existed.

## Rules

Do:

- Build snapshots on the server from stored messages. Never trust a snapshot or parts from the client.
- Copy parts by an allowlist, and test that an unknown part type is dropped.
- Return `404` for another user's chat on every share route, and add the routes to slice 18's cross-user test.
- Keep the public page free of anything from the viewer's own session.

Avoid:

- `srcDoc` on the public page, and any frame without the `sandbox` CSP directive.
- Putting the token in logs. Log the share id.
- A `LIKE` or prefix match on tokens.
