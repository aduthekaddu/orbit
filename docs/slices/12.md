# Slice 12: Deploy

Reach Orbit from your phone or another computer at `https://orbit.aduthekaddu.in`. A Cloudflare tunnel carries the traffic, so no port opens on the host. Cloudflare Access checks who you are before any request reaches Orbit, and Orbit's own login still runs after that.

**Branch** `feat/deploy`. **Depends on** [slice 3](03.md). Ship it after slices 8 and 9, so the sandbox and GitHub tools sit behind Access from the first day they are public.

## Why

Orbit binds to `127.0.0.1:3210`, so it works only on the machine that runs it. Opening a port would put the login page, and later the code sandbox, on the open internet. A tunnel makes an outbound connection to Cloudflare, so nothing listens publicly. Access on the free tier adds a second login, such as a one-time code sent to an allowed email, in front of everything.

## Scope

Ships:

- A `cloudflared` service in `docker-compose.yml`, behind a Compose profile named `public`, that runs the tunnel with a token from `.env`.
- `ORBIT_PUBLIC_URL`, which sets `BETTER_AUTH_URL` and adds the public origin to the trusted origins.
- `scripts/deploy-wizard.sh`, which walks the operator through the Cloudflare dashboard steps that only a person can do.
- A `drive public` command in verify-orbit that checks the public URL from outside.
- A deployment section in the README.

Does not ship:

- Checking the Access JWT inside Orbit. The tunnel is the only public path, and Orbit's own login still runs. Record this as a follow-up in SECURITY.md.
- Any change to the host's existing `cloudflared` install or to `~/kodus`.
- Hosting on a cloud provider.

## Design

### Data shape

```ts
type PublicConfig = {
	publicUrl: string; // "https://orbit.aduthekaddu.in", from ORBIT_PUBLIC_URL
	tunnelToken: string; // CLOUDFLARE_TUNNEL_TOKEN, read only by the cloudflared container
};
```

`resolveAuthBaseUrl(env)` in `src/lib/auth-origins.ts` returns `ORBIT_PUBLIC_URL` when it is set, and `BETTER_AUTH_URL` otherwise. `resolveTrustedOrigins` adds the public origin. better-auth marks cookies `Secure` when the base URL is `https`.

### Request path

```text
phone → Cloudflare edge → Access login → tunnel → cloudflared container → http://orbit:3210 → better-auth login → Orbit
```

The `cloudflared` container reaches Orbit on the Compose network by service name. The host port mapping stays `127.0.0.1:3210:3210`, so local use still works with no Access login.

### Operator steps

These need a person in the Cloudflare dashboard, so the wizard script walks through them one at a time. Build it with the wizard skill. Each step says what to click and what to paste back:

1. Create a named tunnel and copy its token into `.env` as `CLOUDFLARE_TUNNEL_TOKEN`.
2. Add the public hostname `orbit.aduthekaddu.in` with the service `http://orbit:3210`.
3. Create a self-hosted Access application for that hostname.
4. Add an Allow policy with the operator's email, and set the session length to 24 hours.
5. Run `docker compose --profile public up -d` and wait for the tunnel to show as healthy.

Leave alone:

- The host's own `cloudflared` service and its configuration.
- `~/kodus` and its containers.
- Orbit's login and signup rules. Access sits in front of them and replaces nothing.

## Rules

Do:

- Keep the tunnel token in `.env` and out of logs, the wizard's output, and the PR.
- Keep local access on `127.0.0.1:3210` working.
- Turn on the tunnel only through the `public` profile, so a plain `docker compose up` stays local.

Avoid:

- Publishing port 3210 on `0.0.0.0` or any public interface.
- Touching DNS records, Access policies, or tunnels other than this one.

## Build

### Turn 1. Reproduce, then write failing tests

1. Reproduce. Run `curl -sS -o /dev/null -w '%{http_code}\n' https://orbit.aduthekaddu.in` and save the result. The hostname does not serve Orbit yet.
2. Add cases to `src/lib/auth-origins.test.ts`. With `ORBIT_PUBLIC_URL` set, the auth base URL is the public URL and the trusted origins include it. Without it, nothing changes. Run `npm test`. The new cases must fail.
3. Write `drive public`. Without an Access cookie, `GET <public>/` must answer `302` to a `cloudflareaccess.com` URL, and `GET <public>/api/chats` must not answer `200`. Also sign in at `http://127.0.0.1:3210` and open a protected page while `ORBIT_PUBLIC_URL` is set. `GET /api/setup` answers without a session, so it cannot show that local sign-in still works. Run it. It must fail on the first check.

### Turn 2. Make the tests pass

1. Implement the auth base URL and the origins.
2. Add the `cloudflared` service and the env names.
3. Write the wizard script with the wizard skill.
4. Run `npm test`, `npm run typecheck`, `npm run build`, `docker compose build`, and `docker compose --profile public config`. Check that the config output shows port 3210 bound to `127.0.0.1` only.

### Turn 3. Prove it with verify-orbit

1. Ask the operator to run `scripts/deploy-wizard.sh`. You cannot do the dashboard steps.
2. Run `docker compose --profile public up -d`, then `drive public`.
3. Ask the operator to open the public URL on a phone, pass Access, sign in to Orbit, send one message, and send back a screenshot.
4. Run `docker compose logs cloudflared | tail -20` and post the lines that show the tunnel connected. Redact the token if any line contains it.
5. Post the output and the screenshots, update the changelog and the roadmap, and mark the PR ready.

## Done when

- `npm test`, `npm run typecheck`, `npm run build`, and `docker compose build` exit 0.
- Without Access, the public URL redirects to the Access login, and no API route answers `200`.
- After Access and Orbit login, a phone can chat.
- Local use on `127.0.0.1:3210` still works.
- A plain `docker compose up` starts no tunnel.
