# Slice 14. Reading foundation and appearance

Make long replies comfortable to read, and let each person pick a theme, a text size, a reply font, a chat width, and an accent. The settings live in a new `user_preferences` table and paint on the first frame, with no theme flash.

**Branch** `feat/reading-appearance`. **Depends on** nothing. Slices 15, 16, and 18 build on its type scale, its color roles, and its table.

## Why

The maintainer says the app is tiring to read, the font is too small, and everything is black and white. The app tour of `291149c` agrees and shows the cause is size and line length, not contrast:

- 94.6% of the visible characters on the desktop markdown chat are 14px or smaller, and no text is 15 or 16px. Prose is `text-sm leading-6` (`src/components/chat/markdown-text.tsx:112`).
- A desktop line holds about 100 characters, because 14px text sits in a 42.5rem column (`src/app/globals.css:129`). A comfortable line holds 45 to 75.
- Meta text is 11 or 12px. The sidebar group label, the model chip, and the code language are 11px (`text-2xs`, `globals.css:132`). Tool-card headers, form labels, code, and reasoning are 12px.
- Every input is 14px, so iOS Safari zooms the page when a field gets focus. This is inferred from Safari's 16px rule. No real iPhone was tested.
- `h4` and `h5` are body size (`markdown-text.tsx:31-32`).
- Dark is the only theme. `src/app/layout.tsx:18` hard-codes `class="dark"`, `src/app/layout.tsx:12-13` hard-codes the theme color, and `globals.css:7` sets `color-scheme: dark`. Some people find near-black hard to read, and ChatGPT users ask for a text size setting that ChatGPT still lacks.

Contrast is fine today. Gray text measures 5.57 to 5.92 against its background, and the tour found no low-contrast text. This slice must keep it that way in every new theme.

## Scope

Ships:

- A type scale. Prose at 16px with a line height near 1.65. A reading column near 36rem, so a desktop line holds 65 to 75 characters. Inputs at 16px or more at every text size. Meta text at 13px or more. 11px only inside `Kbd`. Distinct `h1` to `h6`.
- Color roles. Status tokens mean status, chart tokens mean series, and the sun stays the one brand color. A light palette, a dim palette, a light syntax palette, and light hairline figure plates.
- Themes `dark`, `dim`, `light`, and `system`. `system` follows the operating system through CSS alone.
- Text size `sm`, `md`, `lg`, `xl`, set as the root font size.
- Reply font `sans` (Geist) or `serif` (Source Serif 4, self-hosted from npm).
- Chat width `normal` or `wide`.
- Accent presets `sun`, `sky`, `rose`, `sand`.
- The `user_preferences` table, keyed by user, with `GET` and `PATCH /api/preferences`.
- An **Appearance** section at the top of `/settings` that saves each change at once.
- First paint from the server layout. The `<html>` element carries the user's choices before any script runs.
- `docs/design.md`, `ARCHITECTURE.md`, and `CHANGELOG.md` updates.

Does not ship:

- Widget and tool-card redesign. That is [slice 15](15.md). This slice only swaps their size classes to the new scale.
- The artifact iframe stylesheet, message collapse, palette truncation, and other phone fixes. That is slice 16.
- Custom CSS, custom colors, or more fonts. Presets only.
- A reply style setting. That is a product call left open in the v1 plan.

## Design

### Data shape

`src/lib/appearance.ts` is pure and safe to import in the browser:

```ts
export const THEMES = ["dark", "dim", "light", "system"] as const;
export const TEXT_SIZES = ["sm", "md", "lg", "xl"] as const;
export const REPLY_FONTS = ["sans", "serif"] as const;
export const CHAT_WIDTHS = ["normal", "wide"] as const;
export const ACCENTS = ["sun", "sky", "rose", "sand"] as const;

export type Appearance = {
  theme: (typeof THEMES)[number];
  textSize: (typeof TEXT_SIZES)[number];
  replyFont: (typeof REPLY_FONTS)[number];
  chatWidth: (typeof CHAT_WIDTHS)[number];
  accent: (typeof ACCENTS)[number];
};

export const DEFAULT_APPEARANCE: Appearance = { theme: "dark", textSize: "md", replyFont: "sans", chatWidth: "normal", accent: "sun" };

export const appearanceSchema: z.ZodType<Appearance>; // z.object of z.enum fields
export function parseAppearance(row: unknown): Appearance; // per field, an unknown value falls back to the default
export function appearanceAttributes(a: Appearance): Record<`data-${string}`, string>; // data-theme, data-text-size, data-reply-font, data-chat-width, data-accent
export function themeColorFor(theme: Appearance["theme"]): Viewport["themeColor"]; // "system" returns two entries with media queries
```

`appearanceAttributes` is the one place that turns a choice into DOM. The server layout and the settings controls both call it.

The default theme is `dark`, so every existing install looks the same after the migration, apart from the new type scale.

### Storage

`user_preferences` in `src/lib/db/schema.ts`, created by `npm run db:generate` as the next free migration (`drizzle/0011_*.sql` if nothing lands first):

| Column | Type | Default |
| --- | --- | --- |
| `user_id` | text, primary key, references `user.id` `ON DELETE CASCADE` | |
| `theme` | text not null | `'dark'` |
| `text_size` | text not null | `'md'` |
| `reply_font` | text not null | `'sans'` |
| `chat_width` | text not null | `'normal'` |
| `accent` | text not null | `'sun'` |
| `updated_at` | integer `timestamp_ms` not null | |

There is no backfill. A user with no row gets `DEFAULT_APPEARANCE`. The first `PATCH` creates the row with `INSERT ... ON CONFLICT(user_id) DO UPDATE SET <changed fields>`, so a repeated `PATCH` converges to the same row. Slice 17 adds `default_connection_id`, `default_model`, and `default_effort` to this table, and slice 18 adds the memory switch. Nothing moves when accounts arrive, because the key is already the user.

`src/lib/preferences.ts` owns the reads and writes. `getPreferences(userId)` reads the row and passes it through `parseAppearance`, which is the boundary for database rows. `savePreferences(userId, patch)` upserts and returns the parsed row.

### Request flow

1. `getSession` in `src/lib/session.ts:5` is wrapped in React `cache`, so the root layout and `src/app/(app)/layout.tsx` share one session lookup per request.
2. `appearanceForRequest()` in `src/lib/preferences.ts` returns the signed-in user's appearance, or `DEFAULT_APPEARANCE` when nobody is signed in. Login and signup therefore stay dark.
3. `src/app/layout.tsx` becomes async. It spreads `appearanceAttributes(appearance)` onto `<html>`, drops the `dark` class, and adds the serif font variable. `export const viewport` becomes `generateViewport()`, which returns `themeColorFor(theme)` and a `colorScheme` of `dark`, `light`, or `light dark`.
4. CSS reads the attributes. No script runs before paint, and there is no `localStorage` copy, so the server row is the only source of truth.
5. In Settings, a control applies `appearanceAttributes(next)` to `document.documentElement` at once, then sends `PATCH /api/preferences` with only the changed field. On success it calls `router.refresh()`, so the server attributes and the theme-color meta match. On failure it puts the old attributes back and shows one error line.

Reading headers in the root layout makes every page dynamic. The signed-in pages already set `dynamic = "force-dynamic"`, so only `not-found` and the auth pages change mode. Check the `npm run build` route table in turn 2 and note the change in the PR.

### Tokens

All values live in `src/app/globals.css`. Components keep using token classes and never read a theme.

Colors. Every color primitive and every color token that differs by theme is written once as `light-dark(<light>, <dark>)`:

```css
:root { color-scheme: dark; --orbit-bg: light-dark(#f7f6f2, #0b0c0f); /* ... */ }
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="system"] { color-scheme: light dark; }
:root[data-theme="dim"] { color-scheme: dark; --orbit-bg: #1b1c20; --orbit-surface: #222328; /* dark-side overrides only */ }
```

`system` then follows the operating system with no script and no duplicated light block. `dim` overrides only the dark-side primitives it changes (page, surfaces, borders, raised, sunken, canvas, popover, skeleton). `light-dark()` ships in Chrome 123, Safari 17.5, and Firefox 120. Turn 1 checks that Tailwind's opacity modifiers, which compile to `color-mix()`, resolve correctly over `light-dark()` values in Chromium and WebKit.

The light values in this plan are starting points. Turn 1 settles them with `src/app/theme-contrast.test.ts`.

| Role | Tokens | Rule |
| --- | --- | --- |
| Page and surfaces | `--background`, `--card`, `--popover`, `--canvas`, `--surface-sunken`, `--surface-raised`, `--accent`, `--secondary`, `--muted` | In light, the page is warm paper, cards are lighter than the page, and wells are darker. In dark and dim, depth still comes from a lighter surface. |
| Text | `--foreground`, `--muted-foreground` | At least 4.5:1 on every surface it sits on, in every theme. |
| Primary action | `--primary`, `--primary-foreground` | Ivory on dark and dim, ink on light. |
| Status | `--info`, `--positive`, `--warning`, `--negative` | Mean info, success, warning, and error. Nothing else uses them. `--destructive` becomes `var(--negative)`, so error red has one source. At least 4.5:1 on `--card`, because callouts set text in them. |
| Series | `--chart-1` to `--chart-5` | Series identity and domain tiles. At least 3:1 on `--card`. Slice 15 is the first user. |
| Brand | `--orbit-sun` behind `--sun` and `--ring` | Set by the accent preset. At least 3:1 on `--background`, the non-text minimum. |
| Code | `--syntax-*` | A light palette added through `light-dark()`. At least 4.5:1 on `--surface-sunken`, except `--syntax-comment` at 3:1. |
| Figures | `--hairline-*` | Already derived from the primitives (`globals.css:71-76`), so they follow the theme. |
| Overlay | `--overlay` (new) | Replaces the raw `bg-black/75` in `src/components/ui/dialog.tsx:29`. |
| Shadows | `--shadow-card`, `--shadow-float` | Their colors move into `light-dark()`, so light cards get a soft drop instead of a black one (`globals.css:137-138`). |

Accent presets set `--orbit-sun` only. `sun` is today's `#ff9e5e` on dark. `sky`, `rose`, and `sand` each get a dark and a light value that pass the 3:1 check. No purple, per `docs/design.md`. `--chart-1` and `--syntax-keyword` stop copying the sun's hex and keep their own values, so an accent change never recolors data or code.

Type. New entries in `@theme`, each with a line height:

| Token | Start value | Use |
| --- | --- | --- |
| `--text-prose` | `1rem`, line height `1.65` | Assistant replies, user messages |
| `--text-input` | `max(1rem, 16px)`, line height `1.5rem` | Composer, message editor, `Input`, palette input, memory fields, code editor textarea |
| `--text-code` | `0.875rem`, line height `1.5rem` | Code blocks, editable code, artifact code tab |
| `--text-meta` | `max(0.8125rem, 13px)`, line height `1.25rem` | Labels, statuses, chips, code language, group labels, snippets, reasoning pill |
| `--text-h1` to `--text-h6` | `1.5`, `1.25`, `1.125`, `1.0625`, `1`, `1rem` | Markdown headings, with weights 600, 600, 600, 600, 600, 500. `h6` is muted. |
| `--text-2xs` | `0.6875rem` (kept) | `Kbd` only |

`--text-3xs` has no users and is deleted. Tailwind's `text-sm` stays for controls such as buttons, sidebar rows, and menu items. `text-xs` and `text-2xs` leave every component except `src/components/ui/kbd.tsx:9`. Inline code keeps `text-[0.85em]`, so it follows the prose size.

Root size. `:root[data-text-size="sm"]` sets `font-size: 93.75%`, `md` keeps `100%`, `lg` sets `112.5%`, and `xl` sets `125%`. Percentages keep the browser's own font-size setting in effect. `--text-input` and `--text-meta` use `max()`, so the `sm` step never drops an input under 16px or meta text under 13px. Without it, meta at `sm` would be 0.8125 times 15px, about 12.2px.

Width. `--container-widget` (`globals.css:129`) splits in two, and every `max-w-widget` caller moves:

- `--container-chat` reads `var(--chat-column)`. `:root` sets `--chat-column` to the measured normal width, and `:root[data-chat-width="wide"]` sets `48rem`. Callers are `src/components/chat/messages.tsx:83,131,155`, `src/components/chat/thread.tsx:69,104`, and `src/components/tools/run-card.tsx:41`.
- `--container-page` stays `42.5rem` for `src/components/settings/settings-form.tsx:166` and `src/components/memory/memory-list.tsx:136`.

The chat width uses rem, so it scales with the text size, and the characters per line stay the same at every step.

Reply font. `next/font/local` loads `@fontsource-variable/source-serif-4` (5.3.1, OFL-1.1) from `files/source-serif-4-latin-wght-normal.woff2` and the italic file, with `variable: "--font-source-serif"` and `preload: false`. A sans reader never downloads it. `--font-reply` is `var(--font-sans)` by default and the serif stack (`var(--font-source-serif), ui-serif, Georgia, serif`) under `:root[data-reply-font="serif"]`. `MarkdownText` sets `font-reply` on its root, so replies, their headings, and reasoning switch. User messages, widgets, and the UI stay sans. If `next/font/local` rejects a path into `node_modules`, copy the two files and the license into `src/app/fonts/` instead. Non-Latin text falls back to the system serif.

Cleanup this slice makes. `@custom-variant dark` (`globals.css:4`) has zero `dark:` users, so it goes with the `dark` class. `Figure` drops `theme="dark"` (`src/components/figure.tsx:16`) and uses the package default, which follows the page's `color-scheme`. The `--hairline-*` custom properties still win, because the package styles have no specificity. `src/components/auth/auth-demo.tsx:96` keeps `theme="dark"`, because the auth pages stay dark.

### Boundaries

- `PATCH /api/preferences` parses its body with `appearanceSchema.partial().strict()` and rejects an empty object. An unknown key or value returns 400. No session returns 401.
- `GET /api/preferences` returns the parsed appearance for the signed-in user.
- Every query in `src/lib/preferences.ts` takes `userId` first and filters on it. There is no route that takes another user's ID.
- Rows from the database go through `parseAppearance`. A bad stored value falls back to its default for that field and is overwritten on the next save.
