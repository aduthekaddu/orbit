# Slice 2 — generative UI

The model can answer with a small UI spec. The chat renders that spec, and a browser reload shows the same UI.

## What ships

- `@json-render/core` and `@json-render/react` at 0.21.3. The unscoped package `json-render` is not on npm.
- Catalog in `src/lib/genui/catalog.ts`. Components are Card, Metric, KeyValue, Table, List, Callout, and Button. Props are zod 4 schemas. Metric, list, table, and key-value values may be strings or numbers. A number is stored as text.
- `render_ui` on the `streamText` call in `POST /api/chat`. The tool input schema is `catalog.zodSchema()`. With more than one component, that schema treats props as an open record, so `parseRenderSpec` in `src/lib/genui/spec.ts` also checks each element's props against that component's zod schema, then runs `validateSpec` on the tree. Failure returns `{ ok: false, error, raw }` and does not throw.
- The assistant message passes `components.tools.by_name.render_ui` to `MessagePrimitive.Parts`. A valid spec goes through `<Renderer>`. A failed check shows the error and the JSON. The thread stays up.
- Button props are `label`, `action` (`"note"`), and `note`. A click stores that note and shows it under the button.
- The model is told to call `render_ui` for those views and to answer in text otherwise. The system string is not `catalog.prompt()`, because that text asks for a JSONL patch stream.
- A settled tool part is stored in `messages.parts` even when the assistant text is empty. Reload reads those parts. No new table.
- `scripts/smoke-genui.ts` talks to `http://127.0.0.1:3211`. The smoke server must be started with `ORBIT_TRUSTED_ORIGINS=http://127.0.0.1:3211` when `BETTER_AUTH_URL` stays on port 3210.

## Run

```bash
npm run typecheck
npm run build
BETTER_AUTH_URL=http://127.0.0.1:3210 \
ORBIT_TRUSTED_ORIGINS=http://127.0.0.1:3211 \
npm start -- -p 3211 -H 127.0.0.1
```

Smoke, with `ORBIT_BASE_URL` and `ORBIT_API_KEY` set in the environment and not printed:

```bash
npx tsx scripts/smoke-genui.ts
```

The script signs up or signs in `smoke@orbit.local`, saves model `deepseek-v4.1-flash`, asks for a `render_ui` card, and checks that the saved assistant parts contain a spec `parseRenderSpec` accepts.

Unit check, no server:

```bash
npx tsx --test src/lib/genui/spec.test.ts
```

## Acceptance

- `npm run typecheck` and `npm run build` succeed.
- The unit check rejects a bad spec and does not throw.
- `npx tsx scripts/smoke-genui.ts` exits 0 against `127.0.0.1:3211`. The saved assistant parts include a `render_ui` result whose spec passes `parseRenderSpec`. The script prints no secrets.
- `GET /api/chats/:id` and `data/orbit.db` both still have that tool part after the request finishes.
- The server on 3211 is stopped after the check. Port 3210 is left alone.
