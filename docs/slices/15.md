# Slice 15. Widgets and tool cards

Make generated UI read as part of the answer, and make finished tool calls step out of the way. A widget renders in the reply on one surface with formatted numbers, status colors, and capped tables. A finished search or memory call shrinks to one line that opens on tap.

**Branch** `feat/widgets-tool-cards`. **Depends on** [slice 14](14.md) for the type scale, the color roles, `--container-chat`, and the light palette.

## Why

The maintainer says the built-in components "scream UI slop" and break on phones. The tour of `291149c` shows why:

- **Three boxes before any content.** `render_ui` goes through `RunCard` (`src/components/chat/messages.tsx:44`), which draws a bordered card with a "Generated UI ... Succeeded" header (`src/components/tools/run-card.tsx:24,41-47`). Inside it, `Card` draws a second border (`src/components/genui/registry.tsx:16`) and `Metric` a third (`registry.tsx:23`). On a 360px phone that is three borders deep.
- **Gray on gray.** Every widget background sits between `rgb(11,12,15)` and `rgb(29,30,36)`, with two text colors. The info and success callouts are gray, and warning uses the error red (`registry.tsx:9-10`). Nothing uses `--info`, `--warning`, or `--chart-*`.
- **Raw numbers.** "1234" and "42000" print as they came (`registry.tsx:25,34,56`). `shown()` in `src/lib/genui/catalog.ts:6` turns every number into a string during parsing, so the renderer cannot tell a number from text.
- **No limit.** The 220-row `[qa:huge]` table is 12,669px tall, 15 phone screens, and hides 4 of its 8 columns with no sign that it scrolls (`registry.tsx:40`).
- **Errors dump JSON.** `[qa:invalid]` shows a zod path and 30 lines of JSON, expanded (`src/components/genui/render-ui.tsx:24`). On a 390px phone, 56.3% of the visible characters on that screen are under 13px.
- **Tool cards never settle.** Every search, memory save, and GitHub call stays a full bordered card with a 12px gray "Succeeded". Names are mixed: "Web search", "Generated UI", and the raw `remember` (`run-card.tsx:21-27`). Every search result has the same gray letter square (`src/components/tools/search-results.tsx:21`), and the three mock results all show "E".

The widgets also break rules that `docs/design.md` already states. Numbers skip `Intl.NumberFormat` (`docs/design.md:88`). The table has no `ScrollFade` (`:89`). Editable text shows no dashed border or pencil at rest (`registry.tsx:104`, `:90`). The button is a raw `<button>` with no focus ring (`registry.tsx:148`, `:91`). The error disclosure starts open (`:93`). The loading state is the word "Building" instead of a `Skeleton` (`render-ui.tsx:70`, `:86`).

## Scope

Ships:

- `render_ui` renders inline in the reply, with no run frame and no status word, on exactly one surface.
- Numbers formatted with `Intl.NumberFormat` and tabular figures. `Metric` gets an optional change with an arrow and a status color.
- Tables with a raised header row, right-aligned number columns, a horizontal `ScrollFade`, and a cap of 12 rows with **Show all N rows**.
- Callouts colored by status. Editable text with its affordance. Buttons through `Button`.
- Widget errors as one line with a collapsed **Details** disclosure. A skeleton while the spec streams.
- Search, GitHub, memory, and unknown tool calls as one line that says what happened. Search and GitHub lines expand to their results. A failed line starts open.
- Plain names for every tool, from one registry.
- Search result tiles colored from the domain, computed locally.
- `docs/design.md` rewritten for widgets and tool cards.

Does not ship:

- A new widget type, or the removal of one. See [Catalog decision](#catalog-decision).
- Changes to the code-run card body. It keeps its source well, output wells, copy buttons, and result line. See [Code runs stay open](#code-runs-stay-open).
- Artifact cards, message collapse, and phone fixes outside widgets and tool cards. That is slice 16.
- Site favicons. Tiles stay local so the browser fetches nothing from a third party.

## Design

### Data shape

Tool presentation is a registry, extended from `toolCards` in `src/lib/tools/metadata.ts:15-25`:

```ts
export type ToolCardLayout = "inline" | "line" | "card";

type ToolCardDefinition = {
  card: ToolCardKind;          // existing: "genui" | "search" | "code" | "github" | "generic"
  layout: ToolCardLayout;      // inline: no frame. line: one line, opens on tap. card: always a full card.
  title: string;               // the plain name
  summary?: (run: ToolRun) => string;
  failedOutput?: (output: unknown) => boolean;
  stoppedOutput?: (output: unknown) => boolean;
};

export type ToolRun = { status: ToolRunStatus; input: unknown; output: unknown };

export function cardFor(name: string): ToolCardKind;          // unchanged
export function layoutFor(name: string): ToolCardLayout;
export function titleFor(name: string): string;               // registry title, "GitHub" names, or the humanized name
export function summaryFor(name: string, run: ToolRun): string;
```

| Tool | Layout | Title | Running | Succeeded | Failed | Cancelled |
| --- | --- | --- | --- | --- | --- | --- |
| `render_ui` | inline | | | | | |
| `web_search` | line | Web search | Searching the web | Searched the web, 3 sources | Search failed | Search stopped |
| `remember` | line | Memory | Saving to memory | Saved to memory | Could not save to memory | Stopped |
| `forget` | line | Memory | Removing a memory | Removed a memory | Could not remove the memory | Stopped |
| `github_*` | line | "List issues on GitHub" from the name | List issues on GitHub | List issues on GitHub, 2 results | List issues on GitHub failed | List issues on GitHub stopped |
| `run_code` | card | Run code | header status as today | | | |
| any other | line | "Do thing" from `do_thing` | Do thing | Do thing | Do thing failed | Do thing stopped |

The counts use "1 source" and "1 result" in the singular. The search count comes from `searchOutputSchema`, which moves from `search-results.tsx:3-8` to a new browser-safe `src/lib/tools/search-output.ts`, so the line and the list parse the same shape. The GitHub count comes from `githubLinks` in `src/lib/tools/github-links.ts:104`. Status still comes from `toolCallRunStatus` in `src/lib/tools/run-status.ts:28`, which this slice does not change.

Widget props change in `src/lib/genui/catalog.ts`:

```ts
const shown = () => z.union([z.string(), z.number()]); // no transform, so numbers stay numbers

Metric: z.object({
  label: text(),
  value: shown(),
  hint: text().nullable().optional(),
  change: z.number().nullable().optional(),                                      // new
  changeFormat: z.enum(["percent", "number"]).nullable().optional(),             // new, default "number"
  changeTone: z.enum(["positive", "negative", "neutral"]).nullable().optional(), // new, default from the sign
}),
```

`changeTone` lets the model say that a drop is good, such as lower costs. Every new prop is optional, so stored specs still parse. `tableWidthIssues` in `src/lib/genui/spec.ts:15-21` takes `(string | number)[][]`.

Formatting lives in a new pure `src/lib/genui/format.ts`:

```ts
const numbers = new Intl.NumberFormat("en-US", { useGrouping: "min2", maximumFractionDigits: 2 });
export function formatValue(value: string | number): string;   // a number goes through `numbers`, a string is returned as it is
export function formatChange(change: number, format: "percent" | "number"): string; // signDisplay "exceptZero", so "+12%" or "-3.5"
export function changeToneOf(change: number, tone?: "positive" | "negative" | "neutral" | null): "positive" | "negative" | "neutral";
export function numericColumns(rows: (string | number)[][]): boolean[]; // true when every non-empty cell is a number or looks like one
export const TABLE_ROW_CAP = 12;
```

`useGrouping: "min2"` writes 42000 as 42,000 and leaves 1234 and the year 2026 alone, so years and short IDs never get a comma. The locale is fixed to `en-US`, because widgets render on the server and the browser, and a locale that differs between them breaks hydration.

Search tiles come from a new pure `src/lib/tools/domain-tile.ts`. `domainTile(url)` returns `{ letter, tone }`. The letter is the first letter or digit of the hostname with `www.` removed, upper case. The tone is a stable hash of the whole hostname, mapped to 1 to 5 for `--chart-1` to `--chart-5`. `example.com`, `example.org`, and `example.net` share a letter and get their own tones.

### Catalog decision

No widget type is added or removed.

- **No removal.** Stored replies keep their `render_ui` specs in `messages.parts`, and `parseRenderSpec` checks them again on every render. Removing `Text`, `Button`, or any other type would turn old replies into error lines. The project rule is that stored user data keeps working.
- **No chart yet.** A chart needs axes, labels for screen readers, and a light and dark palette, which is a design of its own. This slice gives `--chart-*` its first real users (tiles and, later, series) and leaves a chart type as an open question for the maintainer.

### Code runs stay open

A code run's output is often the answer the user asked for, and its card is on the v1 plan's keep list. Its body does not change. The header keeps "Run code", the language tag, and the status word, because the 17 `sandbox*.mjs` scenarios find the card by `data-tool-name`, many read `[data-tool-status]` and the wells, and they need Docker to rerun. The status word turns `text-positive` on success and stays `text-destructive` on failure.

### Flow

`RunCard` stays the one `Override` in `messages.tsx:44`. It reads `layoutFor(toolName)` first:

- **inline.** Returns `<RenderUiPart {...props} />` with no `<section>` and no header.
- **line.** Returns `<ToolLine>` from a new `src/components/tools/tool-line.tsx`. It is a native `<details data-tool-name>` with a `<summary>` line. The summary holds `OrbitMark` while running, the summary text in a span with `role="status"` and `data-tool-status`, and for search up to five domain tiles (three under the `sm` breakpoint). The body sits below with a left hairline, like reasoning. `open` is set when the status is `failed`. The search body is `SearchResults`. The GitHub body is `GithubOutput`. Memory has no body, and the saved text shows on the summary line in muted text after the label. An unknown tool's body is `GenericOutput`.
- **card.** Today's `<section>`, unchanged apart from the status color.

The summary trigger shares one class with the reasoning pill (`src/components/chat/reasoning.tsx:13`), moved to `src/components/chat/disclosure.ts`, so the two disclosures look like one family and change together. A `<summary>` is not covered by the `pointer: coarse` rule in `globals.css`, so it gets `pointer-coarse:min-h-11`.

`<details>` keeps its body in the server markup, so unit tests can still check what the body renders and what it leaves out. It also opens with Enter and Space with no extra code.

### The widget surface

`RenderUiPart` wraps the renderer in one element: `<div data-genui className="my-3 rounded-xl border bg-card p-4 shadow-card max-sm:p-3">`. No registry component draws a border or its own background, with three exceptions. The table header row is a raised fill (`bg-surface-raised`), callouts are a status-tinted fill with a 2px status rule on the left, and code text sits in a sunken well. Those are fills and rules, not boxes.

| Component | After this slice |
| --- | --- |
| `Card` | A `<section>` with a heading at `text-h4` size and an optional muted description. A nested `Card` starts with a top divider instead of a border. |
| `Metric` | Muted label at `text-meta`. Value at `text-2xl` in `num`, through `formatValue`. A change line with `ArrowUpIcon` or `ArrowDownIcon` and `formatChange`, colored `text-positive`, `text-negative`, or muted by `changeToneOf`. Then the hint. |
| `KeyValue` | Two columns, the label column at most 40% and allowed to wrap. Number values through `formatValue` in `tabular-nums`. |
| `Table` | `ScrollFade axis="x" fade="var(--card)"`. Raised header row. Columns from `numericColumns` are right-aligned and `tabular-nums`. The first 12 rows render, then a ghost `Button` "Show all 220 rows". Expanded, the rows render in place with "Show fewer" at the end. No inner vertical scroll. |
| `List` | As today, at prose size. |
| `Text` | Dashed hairline border and a 14px `PencilSimpleIcon` at rest. Hover and focus make the border solid. Code format uses `text-code`, `whitespace-pre`, and a horizontal `ScrollFade` on `--surface-sunken`. |
| `Callout` | `info`, `warning`, and `success` use `--info`, `--warning`, and `--positive` for the rule and the icon (`InfoIcon`, `WarningIcon`, `CheckCircleIcon`) and a 10% tint of the same token for the fill. Title and text stay `text-foreground`. |
| `Button` | The `Button` primitive at `size="sm"`. The note shows once below it, as today. |

Loading. While the spec streams, `RenderUiPart` shows `Skeleton` blocks in the surface: a title bar and three lines. A hidden status says "Building view".

Errors. `Fallback` becomes one line in `text-destructive` with `WarningCircleIcon`, worded "Could not show this view". Below it is a closed `<details>` named **Details** with the error lines and the raw JSON in a `ScrollFade axis="y"` well capped at `max-h-tool-content`. A stopped spec is one muted line, "Stopped", with no details. `data-genui-fallback` stays, because `scripts/qa/genui-qa.cjs:15` uses it.

The system prompt in `catalog.ts:120-131` gains one sentence. "Give Metric a change number when the value moved, and set changeTone when a drop is good." The prop docs come from the schema already.

### Phone

At 360 and 390px:

- The widget surface pads 12px. A wide table scrolls sideways under its fade, and the page never does.
- A capped table is under one screen tall. "Show all N rows" is a full-width ghost button with a 44px hit area.
- The tool line truncates its text with an ellipsis and keeps three tiles. The line is 44px tall on touch.
- The expanded search list keeps today's layout, with tiles at `size-7`.

At 1440px the widget fills `max-w-chat`, and a tool line is as wide as its text.

## Rules

Do:

- Keep `data-tool-name` on every tool root and `data-tool-status` on its status element. Scenarios find cards by them.
- Use status tokens only for status, and chart tokens only for series and tiles.
- Format every number a widget prints through `formatValue`.
- Give every disclosure a visible label, and keep failures open.

Avoid:

- A border inside the widget surface.
- A status word on a line that already says what happened.
- Raw tool names such as `remember` in any visible text.
- Fetching favicons or any other third-party asset.
- Changing a stored spec. Old replies render through the new components as they are.
