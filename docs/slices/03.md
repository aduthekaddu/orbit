# Slice 3: Chat polish

Close the behavior gaps from [issue #11](https://github.com/aduthekaddu/orbit/issues/11) that need no new data, fix the lost-text bug that the [turn model](../../ARCHITECTURE.md#the-rules-of-a-turn) found, and give verify-orbit a browser so later UI slices can prove what they draw.

**Branch** `feat/chat-polish`. **Depends on** nothing. **Refs** #11.

## Why

- A user who retries a failed first message and then presses stop loses the text they watched stream. After reload the reply is gone. The model found this, and a read of `src/app/api/chat/route.ts` agrees. Nobody has reproduced it live yet.
- Issue #11 lists small things that make Orbit feel unfinished next to ChatGPT and Claude. The empty chat offers nothing to tap. The placeholder says "Message orbit". The sidebar shows a chat named "New chat" right under a "New chat" button. The issue comment also reports that the command palette stays open after you pick an item, and that **Save** in settings is out of reach on a 390×568 screen.
- verify-orbit sends HTTP requests only. It cannot prove a click, a layout, or a screenshot. Slices 4, 5, and 6 change what the user sees, so they need a browser drive first.

## Scope

Ships:

1. A `browse` command in verify-orbit that drives Chrome through Playwright and saves screenshots. A `--mock` flag on `launch` starts the mock provider and points the sandbox settings at it.
2. The fix for retry-then-stop. Text you saw survives a stop when there is no older reply to protect.
3. The palette closes when you pick an item and when you press Esc, if the reproduction shows it does not today.
4. **Save** is reachable at 390×568, if the reproduction shows it is not today.
5. An untitled chat shows as `Untitled` in the sidebar, so it never repeats the **New chat** button label.
6. Four starter prompts on the empty chat. A click fills the composer and focuses it. It does not send.
7. The composer placeholder becomes `Ask anything`.

Does not ship:

- Smart titles and message search. They are [slice 6](06.md).
- Branching. It is [slice 4](04.md).
- A first-run hint card for ⌘K. The project rule against helper text rules it out.
- Projects and personas. They are not planned yet.

## Design

### The save decision

Today `onEnd` in `src/app/api/chat/route.ts` returns early on `write.regenerate && interrupted`. That protects an older reply from a half-finished regenerate. It also drops the reply when no older reply exists, which is the bug.

Move the decision into one pure function in `src/lib/messages.ts`:

```ts
type ReplyEnd = {
	regenerate: boolean;
	interrupted: boolean;
	hadReply: boolean;
	visible: boolean;
};

export function shouldSaveReply(end: ReplyEnd): boolean;
```

It returns `false` when `visible` is false. It returns `false` when `regenerate && interrupted && hadReply`. Otherwise it returns `true`. The route computes `hadReply` as `expectedRow !== undefined` for a regenerate. The route keeps calling `upsertMessage` with the same arguments.

### The browse lever

`verify.mjs browse <scenario>` does four things:

1. It checks that the sandbox server is healthy, the same way `doctor` does.
2. It opens Chrome with Playwright. It uses `/usr/bin/google-chrome` when that file exists and Playwright's own Chromium otherwise.
3. It signs up or signs in `verify@orbit.local` and imports `.agents/skills/verify-orbit/scenarios/<scenario>.mjs`.
4. It calls the scenario's default export with `{ page, origin, step, shot }`. `step(name, ok, detail)` prints `PASS name` or `FAIL name: detail`. `shot(name)` saves `.verify/evidence/<scenario>/<name>.png`. The command exits 1 when any step fails.

`launch --mock` starts `scripts/qa/mock-provider.mjs` on `127.0.0.1:3299` and saves settings with base URL `http://127.0.0.1:3299/v1`, key `test-key-not-real`, and the mock model. `cleanup` stops the mock provider too.

The mock provider gains two scenarios:

- `[qa:fail-first]` answers the first request for a given prompt with HTTP 500. It streams text on later requests.
- `[qa:slow]` streams one word every 200 ms for 10 seconds, so a scenario has time to press stop.

### Starters

The starters are a constant array in `src/components/chat/thread.tsx`:

```ts
const STARTERS = [
	{ label: "Make a table", prompt: "Make a table comparing " },
	{ label: "Explain code", prompt: "Explain this code:\n\n" },
	{ label: "Summarize", prompt: "Summarize this in five bullets:\n\n" },
	{ label: "Brainstorm", prompt: "Give me ten ideas for " },
];
```

Each label is a button under the composer in `EmptyState`. A click sets the composer text through assistant-ui's composer API and moves focus to the end of the text. On a phone each button is at least 44 px tall.

## Rules

Do:

- Reproduce each issue #11 finding before you touch its code. If a finding does not reproduce, record the passing scenario output in the PR and drop that item.
- Keep the save rule in `shouldSaveReply`, and have the route call it.
- Fill the composer from a starter. Let the user send.
- Use the visible label text in scenarios, such as `Ask anything` and `Save`, rather than CSS classes.

Avoid:

- Changing the stale-write guard in `planChatWrite`. The fix is in the save decision only.
- Adding helper text, a subtitle, or a hint under the starters.

## Build

### Turn 1. Reproduce, then write failing tests

1. Build the `browse` command, `launch --mock`, and the two mock scenarios. This is the tool every later check uses, so it comes first.
2. Write `retry-stop.mjs`. It sends `[qa:fail-first] hello`, waits for the error box, clicks **Retry**, waits for text, clicks **Stop**, reloads, and checks that the reply text is still there. Save `before-stop.png` and `after-reload.png`. Run it. It must fail on the check after reload.
3. Write `palette.mjs`. It opens the palette with Ctrl+K, picks **Settings** with Enter, and checks that the dialog is gone and the URL ends in `/settings`. It opens the palette again, presses Escape, and checks that the dialog is gone and focus is back on the composer. Run it and record the result.
4. Write `settings-short.mjs`. It sets the viewport to 390×568, opens `/settings`, scrolls **Save** into view, clicks it, and checks for the saved state. Run it and record the result.
5. Write `empty-chat.mjs`. It checks for the placeholder `Ask anything`, four starter buttons, and that clicking **Make a table** fills the composer without sending. It also checks that the sidebar shows `Untitled` for the new chat. Run it. It must fail on the placeholder.
6. Add `shouldSaveReply` cases to `src/lib/messages.test.ts`. Cover a stopped retry with no older reply, which must save. Cover a stopped regenerate with an older reply, which must not save. Cover a finished regenerate, which must save. Cover a reply with nothing visible, which must not save. Export a stub that throws so the file compiles. Run `npm test`. The new cases must fail.
