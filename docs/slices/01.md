# Slice 1 — walking skeleton

A single user can sign up, store a provider on the server, and stream a chat that survives reload.

## What ships

- Next.js App Router chat UI built with assistant-ui. Messages stream from `POST /api/chat` through `ai` `streamText` and `@ai-sdk/openai-compatible`.
- Settings at `/settings`: base URL, API key, model, reasoning effort (`low` / `medium` / `high`). The model control loads `GET {baseURL}/models`, then `https://opencode.ai/zen/go/v1/models` when the base URL is OpenCode Go and the first list fails. Every returned model is in the dropdown, and Custom is a text field. The effort slider is shown when model metadata says reasoning is supported, or when that metadata is missing. It stays hidden when metadata says reasoning is unsupported. Reasoning is sent as `reasoning_effort` (AI SDK `reasoningEffort`). If the provider rejects that field, the request is retried once without it.
- Settings live in SQLite. `GET /api/settings` returns `keySet: true|false` and never the key. When the base URL is `https://opencode.ai/inference/go/openai/v1`, the chat request sets `x-opencode-session` to the chat id on the outgoing fetch.
- If the settings row is missing, `ORBIT_BASE_URL`, `ORBIT_API_KEY`, and `ORBIT_MODEL` seed it.
- Chats and messages are in `data/orbit.db` (Drizzle). The sidebar lists chats. Opening a chat loads its messages.
- better-auth email/password. Signup works only when the `user` table is empty (hook plus a SQLite trigger). Pages and APIs other than `/api/auth/*` and `/api/setup` require a session.
- `Dockerfile` (`node:24-bookworm-slim`) and `docker-compose.yml` publish `127.0.0.1:3210:3210` only. The process inside the container listens on `0.0.0.0` so the host bind is what restricts access.
- `scripts/smoke.ts` (`npx tsx scripts/smoke.ts`) talks to `http://127.0.0.1:3210`.

## Resolved versions

Exact pins that exist were installed as specified: next 16.4.3, `@assistant-ui/react` 0.15.32, `@assistant-ui/react-ai-sdk` 1.4.21, ai 7.0.159, `@ai-sdk/openai-compatible` 3.0.82, drizzle-orm 0.45.4, better-auth 1.7.14.

Ranges were pinned to the newest matching release: react and react-dom 19.3.1, zod 4.6.7, better-sqlite3 13.0.3, drizzle-kit 0.31.11, Tailwind 4.3.3. `@ai-sdk/react` 4.0.163 is the matching AI SDK UI peer.

`json-render@0.21.3` is not on npm (the unscoped package was unpublished in 2016). Slice 2 will use `@json-render/core@0.21.3` and `@json-render/react@0.21.3`, which are published. Nothing from that slice is installed yet.

## Run

```bash
npm install
npm run build
npm start -- -p 3210 -H 127.0.0.1
```

Open `http://127.0.0.1:3210`. The first visit can create the only account.

Smoke, with a provider key already in the environment as `ORBIT_API_KEY` and the base URL as `ORBIT_BASE_URL`:

```bash
npx tsx scripts/smoke.ts
```

The script signs up or signs in `smoke@orbit.local`, saves model `deepseek-v4.1-flash`, posts one chat turn, checks that streamed text arrived, and reads `data/orbit.db` for that chat and both messages.

## Acceptance

- `npm run typecheck` and `npm run build` succeed.
- Logged-out requests to `/`, `/settings`, `/api/chat`, `/api/settings`, and `/api/chats` do not return the app or data.
- A second signup is rejected.
- `GET /api/settings` has no `apiKey` field.
- A chat streams text and, after reload, `GET /api/chats/:id` returns the user and assistant messages.
- Those rows are in `data/orbit.db`.
- Compose publishes only `127.0.0.1:3210`.
- `scripts/smoke.ts` exits 0 against a server on `127.0.0.1:3210` and prints no secrets.
