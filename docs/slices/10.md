# Slice 10: Memory

Let Orbit remember facts about you across chats. The model can save a memory, and Orbit recalls the closest memories before each reply. A `/memory` page lists every memory so you can edit or delete it.

**Branch** `feat/memory`. **Depends on** [slice 7](07.md) for the tool registry, and [slice 6](06.md) for the FTS5 pattern.

## Why

Every chat starts from zero. A user who said "I write Go and deploy to Fly" last week says it again today. ChatGPT and Claude both remember. Orbit can do it without sending memories to a vendor: SQLite stores them, and a local Ollama model makes the embeddings. An embedding is a list of numbers that places similar texts near each other, so a search finds "I deploy to Fly" from the question "where do I host things?".

## Scope

Ships:

- A `memories` table, an FTS5 index over it, and a `sqlite-vec` vector table for 768-dimension embeddings.
- Embeddings from Ollama's `nomic-embed-text` model.
- Hybrid recall, which merges full-text and vector results by rank.
- `remember` and `forget` tools for the model.
- Automatic recall. The top 3 memories for the latest user message go into the instructions for that turn.
- A `/memory` page to list, search, edit, and delete memories.
- Full-text-only recall when Ollama is unreachable, with the state shown on `/memory`.

Does not ship:

- The nightly job that turns chats into memories. That is [slice 11](11.md).
- Memories per project, or shared memories.
- Importing memories from other apps.

## Design

### Data shape

```ts
type MemoryKind = "fact" | "preference" | "summary";

type Memory = {
	id: string;
	kind: MemoryKind;
	text: string; // at most 500 characters
	sourceChatId: string | null;
	sourceMessageId: string | null;
	createdAt: Date;
	lastUsedAt: Date | null;
	embedded: boolean; // false until Ollama has returned a vector for this text
};

type Recall = { memory: Memory; score: number; via: "text" | "vector" | "both" };
```

### Storage

One migration, hand-written because Drizzle cannot describe virtual tables:

- `memories` as a Drizzle table in `src/lib/db/schema.ts`.
- `memories_fts`, an external-content FTS5 table on `memories.text` with insert, update, and delete triggers. Copy the pattern from slice 6.
- `memories_vec`, a `vec0` virtual table with `embedding float[768]`, keyed by the memory's rowid.

`src/lib/db/index.ts` loads the extension with `sqliteVec.load(sqlite)` before migrations run. `sqlite-vec` 0.1.9 ships prebuilt binaries for linux-x64 and linux-arm64, so the Docker image needs no build step for it.

### Embeddings

`embed(texts)` in `src/lib/memory/embed.ts` calls `POST {ORBIT_OLLAMA_URL}/api/embed` with model `nomic-embed-text`. The default URL is `http://127.0.0.1:11434`. It parses the response with zod and checks that each vector has 768 numbers. It times out after 5 seconds. When it fails, the memory is saved with `embedded: false`. A later call to `embedPending()` fills in missing vectors. `/memory` runs it, and slice 11's nightly job runs it too.

### Recall

`recall(query, k)` in `src/lib/memory/recall.ts`:

1. It runs an FTS5 query with the quoting from slice 6's `toMatchQuery`, and takes the top 20 rows.
2. When Ollama answers, it embeds the query and runs a `vec0` nearest-neighbor query for the top 20 rows.
3. It merges the two lists with reciprocal rank fusion, where each row scores `1 / (60 + rank)` in each list. It returns the top `k`.
4. It sets `lastUsedAt` on the rows it returns.

The merge is a pure function, `fuseRanks(textIds, vectorIds, k)`, and has its own tests.

### Tools and instructions

- `remember({ text, kind })` saves a memory, unless one with the same normalized text exists, and returns its id.
- `forget({ id })` deletes one memory.
- Before `streamText`, the route calls `recall(lastUserText, 3)`. If anything comes back, it adds one block to the instructions: "Things the user told you before. Use them only when relevant:" followed by one line per memory.
- The prompt tells the model to call `remember` only when the user states a lasting fact or preference, or asks it to remember something.

### The page

`/memory` sits in the app shell at the same width as settings. It has a search field, a list with kind, text, source chat link, and last used date, an inline edit with **Save** and **Cancel**, and a delete that asks once. A line at the top shows **Embeddings on** or the Ollama error.

## Rules

Do:

- Keep recall working when Ollama is down, and test that case.
- Test `fuseRanks` with hand-built rank lists, not with database output.
- Cap memory text at 500 characters and the injected block at 3 memories.

Avoid:

- Embedding on the request path for anything except the query. Saving a memory embeds after the response, or later through `embedPending`.
- Putting memories in the instructions without the "only when relevant" line.

## Build

### Turn 1. Reproduce, then write failing tests

1. Reproduce. With the real provider, say "I deploy everything to Fly.io" in one chat. In a new chat ask "Where do I host things?" Save both answers. The second chat does not know.
2. Write `store.test.ts`, `recall.test.ts`, and `embed.test.ts` against a temporary `ORBIT_DATA_DIR` and `mock-ollama.mjs`. Cover save and dedupe, an FTS match, a vector match with no shared words, `fuseRanks` order and ties, recall with Ollama down, `embedPending` filling vectors after Ollama comes back, and delete removing the row from all three tables.
3. Write `memory.mjs`. Send `[qa:remember] I deploy to Fly.io`, open `/memory`, and check for the row. Start a new chat and check that the next request to the mock provider carries the memory in its instructions. The mock provider logs request bodies to `.verify/mock-requests.jsonl` for this check. Edit the memory, delete it, and check that the next request no longer carries it. Run the tests and the scenario. They must fail.

### Turn 2. Make the tests pass

1. Load `sqlite-vec` and add the migration. Run it on a copy of an existing database.
2. Implement the store, embeddings, and recall.
3. Add the tools and the instructions block.
4. Build the page and the API routes.
5. Run `npm test`, `npm run typecheck`, and `npm run build`. Then run `docker compose build` and check that the extension loads in the container.

### Turn 3. Prove it with verify-orbit

1. Run `launch --mock` with `ORBIT_OLLAMA_URL` pointing at `mock-ollama.mjs`, then `doctor`, `browse memory`, and `cleanup`.
2. With real Ollama and `nomic-embed-text` pulled, repeat the turn 1 conversation and screenshot the second chat's answer.
3. Seed 5,000 memories in a scratch database and time 50 recalls with Ollama warm. Report p50 and p95. The budget is a p95 under 150 ms including the query embedding. Also report the time to first token with memory on and off, alternating 10 turns each.
4. Post the output and the screenshots, update the changelog and the roadmap, and mark the PR ready.

## Done when

- `npm test`, `npm run typecheck`, `npm run build`, and `docker compose build` exit 0.
- A memory saved in one chat changes the answer in a new chat.
- Recall works with Ollama down, using full-text search only, and `/memory` shows that state.
- `/memory` lists, searches, edits, and deletes. A deleted memory is never injected again.
- Recall p95 is under 150 ms for 5,000 memories.
