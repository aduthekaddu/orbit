# Slice 6: Titles and history search

Give each chat a short title written by the model, and let ⌘K find any message in any chat.

**Branch** `feat/history-search`. **Depends on** [slice 3](03.md) for the browse drive. **Refs** #11 items 5 and 6.

## Why

The sidebar title is the first 80 characters of the first message. A chat that opens with a pasted stack trace is titled with the stack trace. ⌘K finds chats only by title, so a user who remembers a phrase from an answer three weeks ago cannot find it. Both gaps grow with every chat.

## Scope

Ships:

- A title of at most six words, written by the configured model from the first user message. It runs alongside the reply.
- An FTS5 full-text index over message text, kept in sync by SQLite triggers.
- `GET /api/search?q=` that returns matching messages with a highlighted snippet.
- A **Messages** group in the command palette. Picking a result opens the chat and scrolls to the message.

Does not ship:

- Renaming a chat by hand.
- Search over memories. That is [slice 10](10.md), which reuses this index pattern.
- Semantic search with embeddings. That is also slice 10.

## Design

### Titles

`titlePrompt(firstMessage)` in `src/lib/titles.ts` builds the prompt. `cleanTitle(raw)` strips quotes, markdown, and a trailing period, then runs the existing `chatTitle`. Both are pure.

The route starts the title call only when the chat has no stored messages before this turn. It calls `generateText` with the same model, no reasoning options, `maxOutputTokens: 24`, and a 10-second timeout. It does not await the call before streaming. When the call returns, the route saves the title if `chats.title` still equals the fallback title from the first message. A failed call logs a sanitized line and keeps the fallback. The client already refreshes the sidebar on finish. If the title lands later, the next refresh shows it.

### Search index

A hand-written migration, made with `npx drizzle-kit generate --custom --name messages_fts`:

```sql
CREATE VIRTUAL TABLE messages_fts USING fts5(content, content='messages', content_rowid='rowid');
CREATE TRIGGER messages_fts_ai AFTER INSERT ON messages BEGIN
	INSERT INTO messages_fts(rowid, content) VALUES (new.rowid, new.content);
END;
CREATE TRIGGER messages_fts_ad AFTER DELETE ON messages BEGIN
	INSERT INTO messages_fts(messages_fts, rowid, content) VALUES ('delete', old.rowid, old.content);
END;
CREATE TRIGGER messages_fts_au AFTER UPDATE OF content ON messages BEGIN
	INSERT INTO messages_fts(messages_fts, rowid, content) VALUES ('delete', old.rowid, old.content);
	INSERT INTO messages_fts(rowid, content) VALUES (new.rowid, new.content);
END;
INSERT INTO messages_fts(messages_fts) VALUES ('rebuild');
```

`messages` is a normal rowid table, so the external-content form works without a schema change.

### Search query

```ts
type SearchHit = {
	chatId: string;
	chatTitle: string;
	messageId: string;
	role: "user" | "assistant";
	snippet: string; // from snippet(messages_fts, 0, '[', ']', '…', 12)
};
```

`toMatchQuery(input)` in `src/lib/search.ts` is the boundary. It splits the input on spaces, drops empty tokens, wraps each token in double quotes with inner quotes doubled, and adds `*` to the last token for prefix search. Raw user text never reaches `MATCH`. `searchMessages(userId, q)` joins `chats` to keep results to the user's chats, orders by `bm25`, and returns 20 rows at most.

The palette waits 150 ms after the last keystroke, then calls the API. A result links to `/c/<chatId>?m=<messageId>`. If the hit is not on the path already on screen, the thread loads that message's path before it scrolls. On a flat history the path is the whole chat. After slice 4 the path can be an inactive branch. Opening that path does not write `chats.head_id`, so a later reload still opens the last written branch. The thread then scrolls to the element with `data-message-id` equal to that id and briefly marks it with the `--sun` ring. Add `data-message-id` to both message roots if it is missing.

## Rules

Do:

- Quote every token before it reaches `MATCH`, and test input with `"`, `*`, `-`, `NEAR`, and an unmatched parenthesis.
- Scope every search to the signed-in user's chats.
- Keep the fallback title when the title call fails or times out.

Avoid:

- Awaiting the title call before the reply streams.
- Indexing reasoning or tool output. Index `content`, the plain text of the text parts. Later work added one exception, the standard output, standard error, and source of code runs. See [ARCHITECTURE.md](../../ARCHITECTURE.md).

## Done when

- `npm test`, `npm run typecheck`, and `npm run build` exit 0.
- ⌘K finds a message by a word in its text and opens the chat at that message.
- Hostile search input never returns a 500.
- New chats get a short model-written title. A failed title call keeps the old title.
- Search p95 is under 50 ms on 10,000 messages, and time to first token is within 10 percent of the base commit.
