# Slice 16. Messages, artifact cards, phone fixes, rename and delete

Make the thread calm to read on a phone, give artifacts a card and a themed preview, let people rename and delete chats with a five-second undo, and create a chat row only when its first message commits. This covers the second half of step 2 and the rename and delete part of step 0 in `docs/design/v1-plan.md`.

**Branch** `feat/thread-polish`. **Depends on** shipped slice 13 (durable replies and `discardReplyRun`), shipped slice 14 (type scale, 16px fields, theme tokens, and `data-theme`), and shipped slice 17 (`provider_connections`, per-chat model choice, `ReplyLabel`, `FirstRun`, `src/components/ui/sheet.tsx`, and migrations `0013` to `0015`). Works alongside slice 15 (`feat/widgets-tool-cards`).

## Why

The maintainer reads Orbit on a phone, and the tour at `291149c` found the thread fighting them there. A pasted message is 1,218px tall at 390px wide, 1.4 screens, with no way to fold it. On touch screens Copy and Edit sit beside every user bubble and take 88px of horizontal space away from the text. The assistant action bar (`h-7`) also clips 44px touch buttons next to slice 17's `ReplyLabel`. The floating 32px scroll-to-bottom button covers words in the middle of the text. While a long reply streams, the viewport follows the bottom (`autoScroll`), so the reader loses the start of the answer.

Artifacts look unfinished. In the thread an artifact is a plain "Preview" text button (`src/components/chat/code-block.tsx:74-83`) that disables itself whenever `edit?.enabled` is false, which also breaks read-only views planned in slice 22. The preview is an unstyled white page in Times with default controls, because `artifactDocument` writes no stylesheet (`src/lib/artifacts/document.ts:44`). Every download is named `artifact.<lang>` (`src/components/artifacts/artifact-panel.tsx:114`). The Code tab renders unhighlighted text (`artifact-panel.tsx:167`).

Small phone problems add up. Command palette rows grow to 513px inside a 358px dialog and clip mid-letter because `DialogContent` uses `grid` with an implicit `auto` column (`src/components/ui/dialog.tsx:49`). Search snippets show raw `[ ]` markers and raw markdown `#` (`src/lib/search.ts:71`). Code blocks scroll sideways with no wrap option (`code-block.tsx:173`). In the drawer, Settings is an unlabeled email row, Memory has no link, and Sign out acts without asking (`src/components/chat/sidebar.tsx:134-165`). The thread map prompt list only renders at `@[52rem]/thread` and wider (`src/components/chat/thread-map.tsx:108`). The Memory page keeps showing "No provider is saved" after a connection and default model are saved.

Basic chat management is missing. `/api/chats/[id]` answers `GET` only (`src/app/api/chats/[id]/route.ts:10-22`). New chat calls `POST /api/chats` before any message is sent (`src/components/shell/app-shell.tsx:106-119`), and `/` calls `createChat` when no chats exist (`src/app/(app)/page.tsx:11`), so empty "Untitled" chats pile up in the sidebar. In `POST /api/chat`, `ensureChat` inserts a `chats` row before `reserveReplyRun` and `planChatWrite`, so a 429, a 400, or a stale 409 write against a deleted chat id leaves an empty row behind.

## Scope

Ships:

- Rename and delete for chats. `PATCH` and `DELETE` on `/api/chats/[id]`, a row menu on every sidebar item (dropdown on pointer-fine desktop, reused `Sheet` on touch), inline rename, and a five-second client-side undo.
- Deleting a chat stops any active durable reply through `discardReplyRun(id)` before removing rows. Undoing within five seconds reopens the chat and reattaches to a still-running reply.
- Draft chats without empty database rows. `/new` and `/` (when no chats exist) redirect to `/c/<uuid>?new`, and `POST /api/chat` creates the chat row and saves the first user message in one transaction through `beginTurn`.
- One-time custom migration `drizzle/0017_drop_empty_chats.sql` to delete existing chats that have zero messages.
- User messages taller than 14 lines fold to 12 lines with **Show more** and **Show less**.
- On touch screens (`pointer: coarse`), user message Copy and Edit wrap below the bubble, and the assistant action row grows to 44px beside `ReplyLabel`.
- Streaming pins the new prompt to the top through `ThreadPrimitive.Viewport turnAnchor="top"` instead of auto-scrolling to the bottom. A **Jump to latest** button sits centered in an opaque `h-11 bg-background` footer strip and never covers text.
- An artifact card with kind icon (or busy `OrbitMark` while streaming), extracted title, type label, **Edit** (when editable), and **Open** replaces the Preview link and hides raw artifact code in the thread until edited. The preview frame gets an `@layer orbit-base` stylesheet following Orbit's resolved theme and accent tokens. Downloads use a title-derived filename. The Code tab highlights with shared `orbitCodeTheme`.
- A per-block **Wrap** toggle on non-artifact code blocks.
- Command palette rows fit their dialog and truncate cleanly. Search hits return structured `SnippetPart[]` rendered with `<mark>` and stripped of markdown syntax.
- The sidebar footer gets labeled **Memory** and **Settings** links above a plain email account row, and Sign out opens a confirmation dialog.
- Wherever the thread map rail does not fit, a **Prompts** button opens the thread map prompt list inside the existing `Sheet` when a chat has three or more prompts.
- The Memory page replaces `formatDreamStatus` with structured `DreamStatus`, hides a stale "No provider is saved" failure once `resolveChoice` succeeds, formats timestamps in the browser's time zone, and drops deleted chats during dreaming.

Does not ship:

- An `artifacts` table or an Artifacts page. That is slice 21, which should reuse `artifactTitle` and `artifactFileName`.
- A trash folder, server-side soft delete, or `deleted_at` column. Undo is client-side.
- Bulk delete, rename from the chat header, or pinning chats.
- A persisted wrap preference. Wrap is per block and resets on reload.
- Wrap inside code-run card wells (`src/components/tools/code-run.tsx`).
- Share link pages (slice 22). Artifact **Open** is decoupled from edit permission now so slice 22 inherits read-only preview support.

## What shipped differently

The build differs from the plan as first written in these places. The sections below now describe what shipped.

Server:

- The migration is `drizzle/0017_drop_empty_chats.sql`, because `0016_provider_setup_complete.sql` took `0016` first.
- `ensureChat` had a fourth test caller, `src/app/api/chat/route.test.ts`, which moved with the other three.
- `plainText` link text and link targets stop at the next bracket or parenthesis. The earlier pattern took 1.3 seconds on 50,000 `[` characters.
- `renameChat` squeezes runs of whitespace into one space after trimming, so a title stays on one line.
- `POST /api/chat` reads the chat again after `reserveReplyRun`. A chat that existed before the wait and was deleted during it answers `404`, so the send cannot bring it back.
- `applyCandidatesWithSource` drops a candidate from a deleted message before it looks for a memory to merge with, so a deleted chat neither adds nor merges a memory.
- Before hydration, the Memory page holds the dream status line with a no-break space, so the page does not move when the time appears.

Shell:

- **Undo** reopens the deleted chat only while a draft is open, including the draft the delete opened before it loads. A page picked since then stays. Without a reopen, focus moves to the restored row.
- A chat whose `DELETE` succeeded stays hidden until the refreshed list leaves it out.
- A failed rename goes back to the last saved rename while the server list has not caught up with it, not to the older server title.
- Focus moves to the next row after deleting an inactive chat, to the row link after Enter or Escape in a rename, and to the actions button when its menu closes without a choice. The button stays shown until Radix has focused it, because a hidden button lost focus to the page body.
- In the mobile drawer, Escape in a rename field cancels the rename and keeps the drawer open.
- `chatLabel` and `ChatSummary` moved from `sidebar.tsx` to `src/components/chat/chat-row-menu.tsx`, which the sidebar, the palette, and `AppShell` import.
- The touch row menu sheet is titled with the chat's name, so it says which chat the actions change.
- The toast reads "Chat deleted" with **Undo**.
- A skip link is the first Tab stop on every app page, added after review because each sidebar chat now has two Tab stops (its link and its actions button). On a chat it reads **Skip to chat** and focuses the composer. Elsewhere it reads **Skip to content** and focuses the page's `<main>`, which `AppShell` now wraps around each page.
- `pagehide` also writes the pending chat id to `sessionStorage`. The reload's server render can run before the keepalive `DELETE` lands, so the next page hides that chat and sends the `DELETE` again, where `404` also counts as done.
- Offline, `ChatPanel` waits for the `online` event before `router.refresh()`. A refresh while offline made Next.js load the browser's offline page and lose the picked model.
- Confirming **Sign out** first sends any delete still waiting for **Undo** and waits for it, because signing out ends the session before the shell unmounts.
- **Undo** decides from the URL it is pressed on whether to reopen the deleted chat: `/new`, a `/c/<id>?new` draft, or the deleted chat before the draft loads. A chat saved since the delete stays open.
- `dropNewParam` takes the chat id and rewrites only `/c/<that id>`, so a late answer from one draft cannot strip `?new` from another.
- Closing the **Sign out?** dialog returns focus to Sign out without opening its tooltip, so one Escape on a phone closes the drawer as expected.

Thread:

- The opaque **Jump to latest** strip also renders while saved messages load, so the composer keeps its place when they arrive. The button itself shows only with messages.
- `scrollToBottomOnInitialize` is `hasHistory && !focusMessageId`, fixed at mount. assistant-ui never anchors the first message of a chat, so in a chat that started empty the first-load scroll followed the first reply down. The refresh after that reply sets `hasHistory`, and assistant-ui would scroll then.
- A streaming text part keeps a 24px minimum height. The markdown reveal shows no words in its first frame, and the 24px drop pulled the pinned prompt down.
- The user message root takes `-mt-4 pt-4`, so a pinned bubble sits 16px under the header instead of against its border. `scroll-mt-2` keeps prompt jumps 24px under the top.
- On touch, the branch picker shares the line under the bubble with Copy and Edit. With a mouse, the bubble is capped at `min(85%, 100% - 4rem)` so it never wraps under the hover actions.
- The **Prompts** sheet opens scrolled to the current prompt, so a long chat opens there.
- The **Prompts** button shows whenever the rail does not fit, not only below `md`. `ThreadMap` checks whether the rail and the header are displayed. From 768px with the sidebar open the header is hidden, so the button sits at the right end of the **Jump to latest** strip there.
- On touch, `topAnchorMessageClamp` is `{ tallerThan: "13.125em", visibleHeight: "9.125em" }`: the default plus the 44px action row under the bubble. With the default, a pinned tall prompt showed one cut line of text above Copy and Edit. Desktop keeps the default.

Artifacts:

- The card's kind icon sits in a 36px bordered tile on `bg-surface-sunken`, with a 20px icon or busy `OrbitMark`.
- The panel header puts the title first, before the tabs and Close.
- The Code tab sits on `bg-surface-sunken`, the same surface as code blocks.

### When the first message creates a chat

1. **Draft URLs.** Clicking **New chat** in the sidebar, header, or command palette, or pressing the `newChat` shortcut, calls `router.push("/new")` and closes any open drawer or palette. Remove `newChatState`, `newChatPending`, `latestNewChat`, `newChatError`, and the client `POST /api/chats` call from `AppShell` and `Sidebar`.
2. **Server-minted UUIDs.** `src/app/(app)/new/page.tsx` is dynamic (`force-dynamic`), calls `await requireUser()`, and redirects to `/c/${crypto.randomUUID()}?new`. `src/app/(app)/page.tsx` redirects to `/c/${chats[0].id}` when the user has chats, or directly to `/c/${crypto.randomUUID()}?new` when they have none. Minting the UUID on the server works over plain HTTP where browser `crypto.randomUUID` is absent, and redirecting `/` directly avoids a two-hop redirect.
3. **Draft chat page.** `src/app/(app)/c/[id]/page.tsx` reads `query.new !== undefined` alongside `m` and `artifact`. When `getChatForUser(id, session.user.id)` returns `null`, it renders a draft only when `id` is within `LIMITS.id`, `new` is present, and `chatExists(id)` is `false`. Every other missing case calls `notFound()`, so another user's chat id or a deleted chat without `?new` still answers 404.
4. **Model picker and first-run on a draft.** When `isDraft` is true, `ChatPage` passes `{ connectionId: null, model: null, reasoningEffort: null }` to `resolveChoice(session.user.id, ...)`. If no connection or default model exists, or if the default key is unreadable, `ChatPage` renders slice 17's `FirstRun` setup form with zero `chats` rows in SQLite. Once defaults exist, `ChatPanel` mounts with `isDraft={true}`, `initialHistory={{ headId: null, messages: [] }}`, `liveReplyId={null}`, `restorePending={false}`, and the resolved default `choice`. If the user picks a different model or effort in `ModelChip` before sending, `ChatPanel` keeps it in `sendChoice.current` and attaches `modelChoice` to the first `POST /api/chat`.
5. **Atomic turn creation in `POST /api/chat`.** The handler runs these steps in order:
	1. Authenticate (`getSession`), then cap and parse the body (`readJsonBody`, `bodySchema`).
	2. Check ownership without writing. If `chatExists(id)` is true and `getChatForUser(id, userId)` is null, return `404` `{ error: "Not found" }` before reading `storedMessageIds` or resolving connections.
	3. Validate newly added messages against `storedMessageIds(id)` (`413` or `400`).
	4. Validate and resolve `modelChoice` with `resolveChoice(userId, existingChat ?? NO_CHAT_CHOICE, requested)`. Return `404` for an unowned connection id and `400` for unresolved defaults or an unreadable key.
	5. Reserve the chat's durable reply slot with `await reserveReplyRun(id, userId)` (`409` busy, `429` user limit). Then read the chat again. If it existed before the wait and is gone now, return `404`. Resolve the choice again, read `apiKey`, and build `redact` from the settings as they are after the wait.
	6. Run `beginTurn(id, userId, incoming, redact, parsed.data.trigger, parsed.data.editMessageId)` in one synchronous SQLite transaction:
		- Re-check ownership because another request or delete may have raced across `reserveReplyRun`. Return `{ ok: false, error: "not-found" }` if the id belongs to another user.
		- If no `chats` row exists and `trigger === "regenerate-message"`, return `{ ok: false, error: "not-found" }` so retrying a deleted chat cannot resurrect it.
		- Read `messagesBeforeTurn` inside the transaction. If no `chats` row exists, insert `{ id, userId, title: "New chat", createdAt: now, updatedAt: now }`.
		- Call `planChatWrite(id, incoming, redact, trigger, editMessageId)`. If it returns `{ error }`, roll back the transaction (leaving zero empty `chats` rows behind) and return `{ ok: false, error }`.
		- Return `{ ok: true, chat, write, messagesBeforeTurn }`.
	7. Synchronously after `beginTurn` succeeds, with no `await` before `storedAssistantParts` (preserving the `ChatWrite.Plan` atomicity invariant in `.agents/skills/verify-chat-turn/SKILL.md`), call `bindReplyPlan(run, write.id, write.prompt.id)`, pin the resolved model choice with `if (!sameChoice(chatChoice(chat), choice)) setChatChoice(chat.id, choice)`, call `touchChat`, start `startChatTitle`, and read `storedAssistantParts`.
	8. Delete `ensureChat` from `src/lib/messages.ts` and migrate its four test callers (`src/app/api/chat/route.test.ts`, `src/app/api/route-body-limits.test.ts`, `src/lib/connections.test.ts`, `src/lib/model-choice.test.ts`). Keep `POST /api/chats` and `createChat` for scripts and existing scenarios.
6. **Dropping `?new` and syncing with durable replies.** Add a small `dropNewParam()` helper using `window.history.replaceState` (matching `src/components/artifacts/use-artifact.ts:16-21`, preserving `?artifact=` and `?m=`). Call it in two places:
	- Inside `ChatPanel`'s `onReplyId` callback, right when `POST /api/chat` returns HTTP 200 with `x-resumable-stream-id` (proving `beginTurn` committed the chat and prompt rows). Mark `committedDraft.current = true`. If the reader reloads mid-stream, the URL is already `/c/<id>` and `ChatPage` finds the committed row and `liveReplyId` to resume the durable stream. If the user switches away mid-stream before `onFinish`, `ChatPanel` unmount calls `router.refresh()` when `isDraft && committedDraft.current` so the new chat appears in the sidebar.
	- Inside a `useEffect` whenever `!isDraft` (`if (!isDraft) dropNewParam()`). This covers the durable-reply drop-before-headers case. When a request drops before headers, `onReplyId` never runs and `?new` stays in the URL while `ReplyLink` enters `awaiting-reply` and calls `router.refresh()`. If `beginTurn` committed before the drop, `ChatPage` returns `isDraft={false}` with `liveReplyId`, reattaches to the running reply, and clears `?new`. If the request never reached the server (offline, 401, 413, or 500), `ChatPage` keeps `isDraft={true}` and `?new`, avoiding a 404 and keeping `sendChoice.current` intact for retry.
	- When the stream finishes, aborts, or disconnects, `ReplyLink.finish` calls `router.refresh()`, adding the chat and its title to the sidebar without remounting `ChatPanel`.
7. **Draft header title.** `AppShell` renders an empty `<h1>` while on a draft (`/c/<id>?new` with no sidebar entry). `chatLabel`, now in `src/components/chat/chat-row-menu.tsx` with `ChatSummary`, keeps mapping `"New chat"` to `"Untitled"` for chats whose first message has no text or chats created through `POST /api/chats`.

### API changes

All handlers in `src/app/api/chats/[id]/route.ts` parse parameters and bodies through `r`, `LIMITS`, and `readJsonBody` from `src/lib/route-schema.ts` and never import `zod`.

- **`PATCH /api/chats/[id]`**
	- **Path params.** Parse with `r.object({ id: r.text(LIMITS.id).min(1) })`. An invalid id returns `404` `{ error: "Not found" }`.
	- **Body.** Read with `readJsonBody(request, 4096)` (returns `413` `{ error: "Request body is too large." }` over 4 KiB and `400` `{ error: "Invalid chat title" }` if malformed). Parse with `r.object({ title: r.requiredText(LIMITS.chatTitle) }).strict()` (trimmed, 1 to 120 characters, no extra keys).
	- **Auth and ownership.** Call `getSession()` (`401` if absent), then `renameChat(id, session.user.id, parsed.data.title, requestRedactor(session.user.id))`. Return `404` `{ error: "Not found" }` if the chat is missing or owned by another user.
	- **Storage.** Trim the title and squeeze runs of whitespace into one space. Update `chats.title` only and leave `chats.updated_at` untouched so renaming does not reorder the sidebar. Redact stored credentials in the title. A title generator that finishes after a rename does not overwrite it because `replaceFallbackTitle` (`src/lib/messages.ts:101-104`) matches only the fallback title. Renaming to exact `"New chat"` returns the chat to the untitled marker that `chatLabel` renders as `Untitled`.
	- **Response.** Return `200` `{ id, title }`.
- **`DELETE /api/chats/[id]`**
	- **Path params and auth.** Parse with `paramsSchema` and check `getSession()` (`401` if absent).
	- **Ownership first.** Verify `getChatForUser(id, session.user.id)` before aborting anything, so another user cannot stop someone else's running reply (`404` `{ error: "Not found" }`).
	- **Stop active durable reply.** Call `await discardReplyRun(id)` (`src/lib/reply-runs.ts:214-220`), which aborts the server `AbortController` with reason `"discarded"`, waits for `run.done` (closing sandbox containers and GitHub MCP clients), and evicts buffered chunks. In `POST /api/chat`'s `onEnd`, skip `finishChatReply`, `touchChat`, and `embedPending` when `signal.reason === "discarded"` while still awaiting `closeTools()` in `finally`.
	- **Atomic deletion.** `deleteChat(id, session.user.id)` runs in one SQLite transaction. It re-checks `getChatForUser`, explicitly runs `DELETE FROM messages WHERE chat_id = ?` so the `messages_fts_ad` trigger fires per row without relying on cascade trigger behavior, then runs `DELETE FROM chats WHERE id = ? AND user_id = ?`. Return `404` if `deleteChat` returns `false`, or `204 No Content` with an empty body if it returns `true`.

### Empty-chat cleanup migration

Generate `drizzle/0017_drop_empty_chats.sql` with `npx drizzle-kit generate --custom --name drop_empty_chats`. `0016_provider_setup_complete.sql` took the next free index first.

```sql
DELETE FROM chats
WHERE NOT EXISTS (
	SELECT 1 FROM messages WHERE messages.chat_id = chats.id
);
```

- `PRAGMA foreign_keys = ON` is enabled in `src/lib/db/index.ts:61` before `migrate()` runs.
- Deleted rows have zero `messages`, so `messages_fts` stays consistent.
- Any `memories` row whose `source_chat_id` pointed at an empty chat stays in `memories` with `source_chat_id` set to `NULL` via `ON DELETE SET NULL`.
- Slice 17's `chats.connection_id`, `model`, and `reasoning_effort` have no incoming foreign keys and delete cleanly with the row.
- Running the migration SQL twice is idempotent and deletes zero rows on the second pass.

## Rules

Do:

- Keep the invariant that a chat row exists only once its first message commits (outside `POST /api/chats`). Test rollback in `beginTurn`, not only in the UI.
- Delete `messages` before `chats` inside one transaction, run `discardReplyRun(id)` before `deleteChat`, and test `messages_fts` integrity after deletion.
- Return 404 for another user's chat id on `PATCH`, `DELETE`, `POST /api/chat`, and `/c/<id>?new`.
- Keep `planChatWrite`, `setChatChoice`, and `storedAssistantParts` synchronous with no `await` between them, run `scripts/ci/tlc.sh`, and update `docs/architecture/model-sync.json`.
- Use `requestJson` for every client request, including `keepalive: true` deletes.
- Use `r` and `LIMITS` in every route file, never direct `zod` imports.
- Wait on state with `eventually(...)` in tests and scenarios. Never add an unjustified fixed wait (`src/lib/no-fixed-waits.test.ts`).
- Keep labels short (Rename, Delete, Undo, Open, Wrap, Show more, Show less, Jump to latest, Prompts, Memory, Settings, Sign out). Every new touch control has a 44px hit area.

Avoid:

- A `deleted_at` column or read-path filters.
- Creating a duplicate sheet component when `src/components/ui/sheet.tsx` already exists.
- `dangerouslySetInnerHTML` for snippets or artifact titles.
- JavaScript breakpoints for the touch layout of user messages (use `pointer-coarse:`).
- Hardcoded colors in the artifact stylesheet (read Orbit's resolved theme and accent tokens).
- Leaving `ensureChat`, `formatDreamStatus`, or `newChatPending` behind after callers migrate.
