# Slice 16. Messages, artifact cards, phone fixes, rename and delete

Make the thread calm to read on a phone, give artifacts a real place in the conversation, and let people rename and delete chats. This is the second half of step 2 and the rename and delete part of step 0 in the v1 plan.

**Branch** `feat/thread-polish`. **Depends on** slice 14 for the type scale, 16px inputs, the theme tokens, and the resolved theme that the artifact stylesheet follows. Works before or after [slice 13](13.md). The delete flow says what changes once slice 13 has shipped.

## Why

The maintainer reads Orbit on a phone, and the tour at `291149c` found the thread fighting them there. A pasted message is 1,218px tall at 390px wide, 1.4 screens, with no way to fold it. On touch screens Copy and Edit sit beside every user bubble and squeeze it. The 32px scroll-to-bottom button covers words in the middle of the text. While a long reply streams, the view follows the bottom, so the user loses the start of the answer. Users ask ChatGPT for the same fix: "scroll only until the prompt and start of the answer are visible, then stop".

Artifacts look broken. In the thread an artifact is an 11px "Preview" text button (`src/components/chat/code-block.tsx:74-83`). The preview is a white page in Times with default buttons, because the frame document has no stylesheet (`src/lib/artifacts/document.ts:44`). Every download is named `artifact.<lang>` (`src/components/artifacts/artifact-panel.tsx:114`). The Code tab is plain text (`artifact-panel.tsx:167`).

Small phone problems add up. Palette rows are 513px wide inside a 358px dialog and are cut mid-letter. Search snippets show raw `[ ]` markers and raw `#` (`src/lib/search.ts:71`). Code blocks scroll 924px sideways inside 356px with no wrap option. In the drawer, Settings is an unlabeled email row, Memory is missing, and Sign out acts at once (`src/components/chat/sidebar.tsx:127-151`). The thread map prompt list only exists at 52rem and wider (`src/components/chat/thread-map.tsx:107`). The Memory page keeps showing "No provider is saved" after a provider is saved.

Basics are missing. The chat route answers `GET` only (`src/app/api/chats/[id]/route.ts:7`). New chat inserts a row before anything is sent (`src/components/shell/app-shell.tsx:86-98`, `src/lib/messages.ts:271-276`), so empty "Untitled" chats pile up in the sidebar.

## Scope

Ships:

- Rename and delete for chats. `PATCH` and `DELETE` on `/api/chats/[id]`, a menu on each sidebar row, and a five-second undo.
- A chat row exists only once its first message is saved. A one-time migration removes today's empty chats.
- User messages longer than 14 lines fold to 12 lines with **Show more**.
- On touch screens, Copy and Edit sit under the user bubble.
- Streaming follows the reply only until the prompt reaches the top. A **Jump to latest** button sits in a solid strip and never covers text.
- An artifact card with title, type, and **Open** replaces the Preview link. The frame gets a base stylesheet that follows the current theme. Downloads are named after the title. The Code tab is highlighted.
- A **Wrap** toggle on every code block.
- Palette rows truncate with an ellipsis. Snippets render matches as `<mark>` and carry no markdown.
- The sidebar footer gets labeled **Memory** and **Settings** rows, and Sign out asks first.
- The thread map prompt list opens as a bottom sheet on phones.
- The Memory page drops the stale provider error and says when dreaming last ran.

Does not ship:

- An `artifacts` table or an Artifacts page. That is slice 21, which should reuse `artifactTitle` from this slice.
- A trash folder or server-side soft delete. Undo is client-side (see the delete flow).
- Bulk delete, rename from the header, or pinning chats.
- The model picker in the phone header. That is slice 17.
- A saved wrap preference. Wrap is per block and resets on reload.
- Wrap in the code-run card wells (`src/components/tools/code-run.tsx`).

### New chat without an empty row

1. **New chat** in the sidebar, the header, the palette, and the `newChat` shortcut calls `router.push("/new")`. The `newChatPending` state and its `fetch("/api/chats")` go away.
2. `src/app/(app)/new/page.tsx` is dynamic and redirects to `/c/<crypto.randomUUID()>?new`. The server makes the id, so a plain-HTTP origin without `crypto.randomUUID` in the browser still works.
3. `src/app/(app)/c/[id]/page.tsx` renders an empty `ChatPanel` when `getChatForUser` returns null, the `new` parameter is present, and `chatExists(id)` is false. In every other missing case it calls `notFound()` as today, so a deleted chat or another user's id still gives 404.
4. On the first send, `POST /api/chat` calls `beginTurn`. It runs in one transaction. It returns `not-found` when the id belongs to another user. It inserts the chat row when none exists, runs `planChatWrite`, and deletes the row it just inserted when the plan returns an error. This closes a second leak. Today `ensureChat` (`messages.ts:48-59`) inserts before `planChatWrite` (`route.ts:51-56`), so a stale tab posting to a deleted id leaves an empty row behind. `ensureChat` is deleted. The route keeps calling `storedMessageCount` first for the title logic.
5. `onFinish` in `chat-panel.tsx:62` drops `new` from the URL with `window.history.replaceState` before its `router.refresh()`, the same way `use-artifact.ts:16-21` edits the query. It does so only when `isError`, `isAbort`, and `isDisconnect` are all false, because only a clean finish proves `beginTurn` saved the row. Next.js points `router.refresh()` at the replaced URL (`next/dist/client/components/app-router.js:302`). So dropping `new` when the run starts would make a failed first send (offline, an expired session, or Stop before the server answers) refresh into `notFound()` and lose the message. A provider error after `beginTurn` keeps `new` too, which is harmless because the page finds the row. The path does not change, so `ChatPanel` is not remounted, and the refresh adds the chat to the sidebar.
6. `/` with no chats redirects to `/new` instead of calling `createChat` (`src/app/(app)/page.tsx:11`).
7. The header title for a draft is empty. `chatLabel` keeps mapping `New chat` to `Untitled` for the rare chat whose first message has no text.

`POST /api/chats` and `createChat` stay. `scripts/smoke.ts`, `scripts/smoke-genui.ts`, `scripts/bench-search.ts`, and 41 `page.request.post` calls across the verify-orbit scenarios create chats through them.

### Rename

The row menu's **Rename** turns the row into an input with the current title selected. Enter or blur saves. Escape cancels. An empty or unchanged value cancels without a request. The sidebar shows the new title at once and rolls back with "Could not rename" on a failed request. `PATCH` stores the trimmed title and leaves `updated_at` alone, so a rename does not move the chat to the top. Renaming to exactly `New chat` makes the chat untitled again, because that string is the untitled marker that `touchChat` (`messages.ts:76-82`) checks. An automatic title that finishes after a rename does not overwrite it, because `replaceFallbackTitle` (`messages.ts:89-92`) only replaces the fallback title.

### Delete with undo

1. **Delete** in the row menu dispatches `delete`. The row disappears from the sidebar and the palette, and a toast says "Chat deleted" with **Undo**.
2. If the deleted chat is open, the app goes to `/new` at once. **Undo** brings the row back and, when `wasOpen` is true, returns to `/c/<id>`.
3. After five seconds, `expire` moves the chat to `committing` and `AppShell` sends `DELETE /api/chats/<id>`. The timer pauses while the toast has hover or focus, so a keyboard user can reach Undo.
4. `pagehide`, and `visibilitychange` to hidden, dispatch `expire` and send the request with `fetch(..., { method: "DELETE", keepalive: true })`. A closed tab still deletes. If the browser kills the tab without either event, the chat stays. It never vanishes without the user asking.
5. `204` or `404` dispatch `committed`. Any other answer or a network error dispatches `failed`. The row returns and the toast says "Could not delete" for five seconds.

The server deletes in one transaction. `deleteChat` first checks with `getChatForUser` that the chat belongs to the caller, since `messages` has no user column. It then runs `DELETE FROM messages WHERE chat_id = ?`, so the `messages_fts_ad` trigger (`drizzle/0002_messages_fts.sql`) fires for each row without relying on cascade behavior. Last it deletes the chat row with `user_id` in the `WHERE`. Foreign keys are on (`src/lib/db/index.ts:24`).

Prior art. Delaying the irreversible request on the client is the pattern behind Gmail's "Undo send". A `deleted_at` column was considered and rejected. Every read path would need a filter (`listChats`, `getChatForUser`, `searchMessages`, the dream query, `beginTurn`), and a missed filter would show deleted chats in search.

**With slice 13.** Before deleting rows, `DELETE` calls slice 13's per-chat stop, which aborts the server-side `AbortController`, and clears the chat's saved stream. Use the function names `13.md` gives. If this slice ships first, slice 13 adds that call and a test. Before slice 13, the route needs nothing. `upsertMessage` returns false when the chat or prompt row is gone (`messages.ts:123-136`), so a reply that ends after the delete is not saved.

### Artifacts and code blocks

- **Card.** **Open** never depends on edit permission. Today `disabled={!edit?.enabled}` (`code-block.tsx:77`) turns Preview off in every read-only view, and slice 22's share page is read-only. For an artifact language, `CodeHeader` renders an artifact card and `SyntaxHighlighter` renders nothing, unless the block is being edited. The card is `rounded-lg border bg-card shadow-card` at column width. It shows a kind icon (`BrowserIcon`, `FileSvgIcon`, `AtomIcon`), the title on one line with an ellipsis, the type label, and an **Open** button labeled `Open <title>` for screen readers. **Edit** shows when `edit.enabled` and opens the existing `CodeEditor` under the card. While the reply streams, Open is disabled and `OrbitMark` is busy. The card keeps registering the artifact as `CodeHeader` does today (`code-block.tsx:55-61`).
- **Title.** `artifactTitle` uses an HTML `<title>`, then the first `<h1>` or `<h2>`, with tags stripped and `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&#39;` decoded. SVG uses its `<title>`. React uses the default export's name (`export default function TodoList` gives `TodoList`). The fallbacks are `HTML page`, `SVG image`, and `React component`. Cap at 80 characters.
- **Download.** `artifactFileName` keeps letters and numbers in any script, turns other runs into `-`, trims to 60 characters, lowercases, and adds `.<language>`. An empty slug gives `artifact.<language>`. `Artifact HTML` downloads as `artifact-html.html`.
- **Panel.** The panel header shows the title next to the tabs. The Code tab uses `Highlight` with `orbitCodeTheme`, moved from `code-block.tsx:20-37` to `src/components/chat/code-theme.ts` so both import it. Pass `artifact.language`. Check that Prism tokenizes `svg` (an alias of `markup`).
- **Base stylesheet.** `artifactDocument` puts one `<style>` after the CSP meta and before the body. Every rule sits in `@layer orbit-base`, so any unlayered style the artifact writes wins without a specificity fight. It sets `color-scheme`, body background, text color, a system font stack (`ui-sans-serif, system-ui, sans-serif`, since the frame's `font-src data:` cannot load Geist), 16px text at 1.6 line height, 16px padding, headings, links in the accent color, `button`, `input`, `select`, and `textarea` with the surface, border, radius, and a focus ring, tables with hairline borders, `pre` and `code` in `ui-monospace`, and `img, svg { max-width: 100% }`. An SVG artifact is centered. The CSP string does not change.
- **Theme.** `ArtifactPanel` reads `ArtifactTheme` from the computed tokens on `document.documentElement` (`--background`, `--card`, `--foreground`, `--muted-foreground`, `--border`, `--primary`, `--ring`), plus the scheme slice 14 resolves. Use slice 14's hook or attribute if it has one. Otherwise add `useArtifactTheme()` in `src/components/artifacts/`, which re-reads on a `MutationObserver` of `<html>` attributes and a `prefers-color-scheme` listener. A theme change rebuilds the document, which reloads the artifact. That is accepted.
- **Wrap.** `CodeHeader` gets a **Wrap** text button with `aria-pressed`, beside Edit and Copy. Wrapped, the `pre` drops `w-max` (`code-block.tsx:173`) and uses `whitespace-pre-wrap break-words`. The 14-line cap still applies by height.

### Palette and search snippets

- **Truncation.** `DialogContent` is a CSS grid with an implicit `auto` column (`src/components/ui/dialog.tsx:49`). Its child grows to the max-content width of the `truncate` spans, which is the 513px row. Add `grid-cols-1` to the base class, which is `minmax(0, 1fr)`, and give each palette text span `min-w-0`. This cause is inferred from the class list. Turn 1 confirms it by measuring the `cmdk` root.
- **Snippets.** `searchMessages` asks FTS5 for `snippet(messages_fts, 0, char(57344), char(57345), '…', 12)`. Those are private-use characters that never appear in normal text. The function runs `plainText` on the snippet, then splits on the two characters into `SnippetPart[]`. A literal `[qa:remember]` stays text. The palette renders each match as `<mark className="bg-transparent font-medium text-foreground">` inside the muted line, and the chat title line stays plain. `plainText` is `chatTitle`'s regex chain from `messages.ts:63-69`, extracted so titles and snippets share one rule.

### Memory page

`MemoryPage` passes `dreamStatus(latestRun(), lastDoneRun(), providerReady)` to `MemoryList`. `lastDoneRun` is `latestDone` without its date bound. A failed run whose error is `No provider is saved` counts as not failed once a provider is saved. The status shows the last done run instead, or nothing. The client formats times in the reader's time zone.

- `done`: "Last dream Nov 14, 03:04. 3 chats, 3 added, 0 merged"
- `running`: "Dreaming since 03:00"
- `failed`: "Dream failed Nov 14, 03:04. <error>" in `text-destructive`

### Boundaries

- `PATCH` parses its body with `renameBody`. Both new handlers check the `id` with `idSchema`. Code behind them trusts the types.
- `renameChat` and `deleteChat` take `userId` and return `null` or `false` for another user's chat. The route answers 404, the same as a missing chat. If slice 18 has shipped, add both routes to its cross-user route test. If not, slice 18 adds them.
- `ArtifactTheme` values are parsed with zod (`/^[#a-z0-9(),.%\s/-]+$/i`) before they go into the `<style>` string, so a token value cannot close the tag.
- Snippet parts render as React text and `<mark>` elements. No HTML string from the database reaches the DOM.
