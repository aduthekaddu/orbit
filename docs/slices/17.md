# Slice 17. Model and effort in the chat, plus Anthropic

Pick the model and the effort for each chat from the composer. A popover opens on desktop and a bottom sheet on a phone. Provider keys move into a `provider_connections` table, encrypted at rest. Anthropic joins as a native provider. Each reply names the model that wrote it and says when the provider ignored the effort.

**Branch** `feat/model-picker`. **Depends on** slice 14, which creates `user_preferences`. Covers gap G1 in `docs/design/gap-analysis.md` and step 3 of `docs/design/v1-plan.md` (both on the `docs/gap-analysis` branch).

## Why

Model and effort are one global setting today. They live on the single `settings` row (`src/lib/db/schema.ts:82-93`), and the chat route reads `settings.model` and `settings.reasoningEffort` for every chat (`src/app/api/chat/route.ts:123-136`). The model chip in the composer is a link to `/settings` (`src/components/chat/composer.tsx:29-35`). On a phone, changing effort means leaving the chat. Claude.ai and ChatGPT both put the model and effort in the composer, and Claude applies a change from the next reply.

Three more problems sit under the picker:

- **Effort is dropped without a word.** Orbit has `low`, `medium`, and `high` (`src/lib/settings.ts:8`). When a provider rejects `reasoning_effort`, `fetchWithReasoningFallback` resends without it (`src/lib/provider.ts:50-61`) and the reply looks normal. Open WebUI shipped the same silent drop (open-webui#33584).
- **Keys sit in plain text.** `settings.api_key` is a plain column. Slice 18 adds more people, so keys must be encrypted from the first row of the new table.
- **Anthropic only works through its OpenAI-compatible layer.** Anthropic calls that layer not production-ready. Through it, effort is ignored, thinking text does not come back, and prompt caching is off.

## Scope

Ships:

- `provider_connections` with keys encrypted by AES-256-GCM. The `settings` provider fields migrate into one row, then leave `settings`.
- Two connection kinds, `openai-compatible` and `anthropic`. Anthropic runs through `@ai-sdk/anthropic` 4.0.94.
- Per-chat `connection_id`, `model`, and `reasoning_effort`. A chat pins its choice on the first send. Null falls back to the user's defaults.
- User defaults in `user_preferences`: `default_connection_id`, `default_model`, `default_effort`.
- One effort enum, `'none' | 'low' | 'medium' | 'high' | 'xhigh' | 'max'`, and one adapter per connection kind. Levels a model does not take are disabled.
- The picker. A popover on desktop, a bottom sheet under 48rem.
- Show and hide models, with badges for images, tools, reasoning, and context size.
- A label on each reply with the model that wrote it and its effort, marked when the provider adjusted or ignored the effort.
- Prompt caching for Anthropic through `cacheControl`.

Does not ship:

- Sharing connections between accounts, signup modes, or SSRF checks per hosting mode. Those are slice 18, through `policyFor(mode)`.
- Usage and cost per reply (gap G4). It builds on the reply record added here.
- Files and images in messages (slice 20). The image badge only describes the model.
- Anthropic's refusal fallbacks (`fallbacks: "default"`). See the open question in the Rules.

## Design

### Data shape

```ts
// src/lib/effort.ts
export const EFFORTS = ["none", "low", "medium", "high", "xhigh", "max"] as const;
export type Effort = (typeof EFFORTS)[number];
export type EffortOutcome = "applied" | "adjusted" | "ignored";

// src/lib/connections.ts
export type ProviderConnection =
  | { id: string; userId: string; kind: "openai-compatible"; label: string; baseUrl: string; createdAt: Date }
  | { id: string; userId: string; kind: "anthropic"; label: string; createdAt: Date };
export type PublicConnection = Omit<ProviderConnection, "userId"> & { keySet: true };

// src/lib/model-list.ts
export type ModelCaps = {
  images: boolean | null; // null means the provider did not say
  tools: boolean | null;
  reasoning: boolean | null;
  contextTokens: number | null;
  efforts: Effort[] | null; // the levels the model takes, or null when unknown
};
export type ListedModel = { id: string; label: string; caps: ModelCaps };

// src/lib/model-choice.ts
export type ModelChoice = { connectionId: string; model: string; effort: Effort };
export type ReplyRecord = { connectionId: string; model: string; effort: Effort | null; effortOutcome: EffortOutcome | null };
```

`ListedModel` replaces today's `{ id, reasoning }` (`src/lib/provider.ts:10-13`). Migrate `src/lib/model-picker.ts`, the settings form, and `src/lib/provider.test.ts` to it. The settings form's `Connection` type (`src/lib/settings-form.ts:4-8`) means "can the model list load". Rename it to `ModelListStatus`, so "connection" means one thing in the code.

### Tables

- `provider_connections`. `id` text primary key, `user_id` text NOT NULL references `user.id` ON DELETE CASCADE, `kind` text NOT NULL, `label` text NOT NULL, `base_url` text, `api_key_ciphertext` text NOT NULL, `created_at` integer NOT NULL. A `check()` (drizzle-orm 0.45 has it in `sqlite-core`) requires `base_url` for `openai-compatible` and forbids it for `anthropic`. Index on `user_id`.
- `hidden_models`. Primary key (`user_id`, `connection_id`, `model_id`), both foreign keys ON DELETE CASCADE. This column set is not in the shared contract. It is keyed by user so slice 18's shared connections let each member hide models without touching the admin's list. Show is the default, so the table stores only hidden rows.
- `user_preferences`. Add `default_connection_id` (text, references `provider_connections.id` ON DELETE SET NULL), `default_model` (text), and `default_effort` (text).
- `pending_connection`. At most one row (`id` integer primary key with `check (id = 1)`), with `base_url`, `api_key_ciphertext`, `model`, `effort`, and `created_at`. It holds the provider of an install that nobody has signed up to yet, until the first account takes it.
- `chats`. Add nullable `connection_id`, `model`, and `reasoning_effort`. The three are set together or all null. One function, `setChatChoice`, writes them, and a zod schema reads them, because a `CHECK` on `chats` would make drizzle rebuild the table under `messages` (inferred from how drizzle-kit handles new constraints on SQLite). No foreign key, because `ON DELETE SET NULL` would null one column of three. `deleteConnection` clears all three in its transaction.
- `messages`. Add nullable `connection_id` (references `provider_connections.id` ON DELETE SET NULL), `model`, `reasoning_effort`, and `effort_outcome`. Only assistant rows fill them. Old replies stay null and show no label. These are columns rather than JSON so G4 can query them.

### Encryption

`src/lib/secrets.ts` exports `encryptSecret(plain)` and `decryptSecret(stored)`. The key is 32 bytes. It comes from `ORBIT_SECRET_KEY` (64 hex characters) or from `data/secret-key`, created on first use with mode `0600`. This is the same handling as `authSecret` in `src/lib/auth.ts:13-25`. The stored form is `v1.<iv>.<tag>.<ciphertext>` in base64url, with a fresh 12-byte IV per write and the associated data `provider_connections.api_key`. A wrong key, a changed byte, or a lost key file throws `SecretUnreadable`. The chat route turns that into 400 "Re-enter the API key for <label>." The README backup note names `data/secret-key` next to `orbit.db`.

### Migration

Use the next three free migration numbers. They are 0011 to 0013 if nothing lands first.

1. Generated. Add the new tables and columns to `src/lib/db/schema.ts` and run `npm run db:generate`.
2. Custom (`npx drizzle-kit generate --custom`). Move the data. It calls two SQL functions that `src/lib/db/index.ts` registers before `migrate` runs, the way `orbit_clean_output` is registered at `db/index.ts:28` for migration 0004. `orbit_encrypt_secret(text)` encrypts with the key above. `orbit_url_host(text)` returns the URL's host for the label.

```sql
INSERT INTO provider_connections (id, user_id, kind, label, base_url, api_key_ciphertext, created_at)
SELECT lower(hex(randomblob(16))), u.id, 'openai-compatible', orbit_url_host(s.base_url), s.base_url,
       orbit_encrypt_secret(s.api_key), cast(unixepoch('subsecond') * 1000 as integer)
FROM settings s JOIN (SELECT id FROM user ORDER BY created_at LIMIT 1) u
WHERE s.id = 1 AND s.base_url <> '' AND s.api_key <> '';
--> statement-breakpoint
INSERT INTO user_preferences (user_id, default_connection_id, default_model, default_effort, updated_at)
SELECT c.user_id, c.id, nullif(s.model, ''), s.reasoning_effort, CAST(strftime('%s', 'now') AS integer) * 1000 FROM provider_connections c, settings s WHERE s.id = 1
ON CONFLICT(user_id) DO UPDATE SET default_connection_id = excluded.default_connection_id,
  default_model = excluded.default_model, default_effort = excluded.default_effort, updated_at = excluded.updated_at;
--> statement-breakpoint
INSERT INTO pending_connection (id, base_url, api_key_ciphertext, model, effort, created_at)
SELECT 1, s.base_url, orbit_encrypt_secret(s.api_key), nullif(s.model, ''), s.reasoning_effort,
       cast(unixepoch('subsecond') * 1000 as integer)
FROM settings s
WHERE s.id = 1 AND s.base_url <> '' AND s.api_key <> '' AND NOT EXISTS (SELECT 1 FROM user);
```

3. Generated. Remove `base_url`, `api_key`, `model`, and `reasoning_effort` from `settings` in the schema and run `npm run db:generate`.

Stored `low`, `medium`, and `high` are valid efforts, so nothing is rewritten. With no account yet, step 2 moves the provider into `pending_connection` instead. That state comes from an install the environment seeded on first boot that nobody signed up to. `seedSettings` copies the environment only once (`db/index.ts:60-61`), so if the variables are gone by the upgrade, the stored copy is the only one, and step 3 must not take it with the columns.

### The effort adapter

One module, `src/lib/effort.ts`, owns every rule.

- `effortLevels(kind, caps)` returns the enabled levels.
  - `openai-compatible`. `[]` when `caps.reasoning === false`. Otherwise `caps.efforts`, or all six when the list does not say.
  - `anthropic`. The levels whose `capabilities.effort.<level>.supported` is true in the Models API. `none` only when `capabilities.thinking.types.disabled.supported` is true. That field name is inferred from the `thinking.types` shape and must be checked against a real `GET /v1/models` response in turn 1. Claude Opus 5.5 cannot disable thinking, so `none` is off for it.
- `effortCallOptions(kind, effort, levels)` returns the `streamText` options.
  - `openai-compatible`. `{ reasoning: effort }` when the level is enabled, else `{}`. The provider maps the top-level option to `reasoning_effort` (`node_modules/@ai-sdk/openai-compatible/dist/index.js:445`). Drop the duplicate `providerOptions.orbit.reasoningEffort` from `reasoningOptions` (`provider.ts:116-123`) and delete that function.
  - `anthropic`. Always `providerOptions.anthropic.cacheControl = { type: "ephemeral" }`, which the provider sends as top-level `cache_control` (`@ai-sdk/anthropic` 4.0.94, `src/anthropic-language-model.ts:844`). For `none`, `thinking: { type: "disabled" }`. For any other level, `effort` plus `thinking: { type: "adaptive", display: "summarized", blockBinding: { prefixMismatchBehavior: "drop_block" } }`. The provider sends `effort` as `output_config.effort` and adds the `thinking-binding-controls-2026-08-01` beta itself (`anthropic-language-model.ts:807-809`, `:1113-1115`). `display: "summarized"` is needed because current Claude models omit thinking text by default, which would look like a long pause. `drop_block` matters because Orbit's **Edit reply** changes an earlier assistant turn in place (`updateMessageText`, `src/lib/messages.ts:214`), and on current models that would turn the replayed thinking blocks into a 400.
- `effortOutcome({ sent, warnings, dropped })`. `null` when no effort was sent. `ignored` when `fetchWithReasoningFallback` removed it. `adjusted` when any `start-step` warning has `feature: "reasoning"`. Otherwise `applied`. Both providers use that feature name (`@ai-sdk/provider-utils` `dist/index.js:2080`, `@ai-sdk/anthropic` `src/anthropic-language-model.ts:3496`). Warnings ride on the `start-step` stream part (`node_modules/ai/dist/index.d.ts:3104-3108`).

`fetchWithReasoningFallback` takes an `onDropped` callback, so the drop is reported instead of hidden.

### Models

`listModels(connection)` in `src/lib/model-list.ts` returns `ListedModel[] | null`.

- `openai-compatible`. Today's fetch (`provider.ts:165-230`) with a richer parser. It reads `capabilities.reasoning` and `reasoning` as today (`provider.ts:130-139`), and adds `context_length` or `context_window`, `architecture.input_modalities` containing `image`, and `supported_parameters` containing `tools` or `reasoning`. These field names come from OpenRouter-style lists and are inferred. Unknown stays `null`, and `null` shows no badge.
- `anthropic`. `GET {ORBIT_ANTHROPIC_BASE_URL}/models?limit=1000` with `x-api-key` and `anthropic-version: 2023-06-01`, the version the provider sends (`@ai-sdk/anthropic` `src/anthropic-provider.ts:166`). Parse with zod: `id`, `display_name`, `max_input_tokens` for context, `capabilities.image_input.supported`, `capabilities.thinking.supported`, and `capabilities.effort.<level>.supported`. Tools are `true` for every listed Claude model (inferred). Follow `has_more` with `after_id` until done (the pagination field names are inferred; check them in turn 1). This is a plain `fetch` and not the Anthropic SDK, because the model list is the only call outside the AI SDK and Orbit already lists models this way.

The five-minute cache in `provider.ts:183-202` is keyed by connection id instead of base URL and stores `ModelCaps`. `modelAllowsReasoning` (`provider.ts:232-240`) goes away. The route asks `effortLevels` with the cached caps, and on a miss it sends the effort and lets `effortOutcome` report what happened.

### Flow

1. The picker holds a pending `ModelChoice` per chat in panel state. `orbitChatTransport` sends it as `modelChoice` in the body, next to `editMessageId` (`src/lib/chat-transport.ts:13-15`).
2. `POST /api/chat` parses `modelChoice` with zod. It resolves the choice with `resolveChoice(userId, chat, requested)`, which returns `{ ok: true; choice } | { ok: false; reason: "no-connection" | "no-model" | "key-unreadable" }`. A `connectionId` that is not the user's is 404. Resolution order is the request, then the chat's three columns, then the user's defaults.
3. After `planChatWrite` succeeds, the route calls `setChatChoice` when the chat's columns are null or differ. A chat pins its model on the first send, so a later change of the defaults does not move old chats.
4. `languageModelFor(connection, model, chatId, { onDropped })` in `provider.ts` returns `orbitModel(...)` for `openai-compatible` (`provider.ts:73-90`) or `createAnthropic({ apiKey, baseURL })(model)`. Title generation (`route.ts:77-82`) and dreaming (`src/lib/memory/dream.ts:372-378` and `:427-428`) use it too. Before slice 18, dreaming takes the defaults of the only account.
5. A tap on `result.stream` collects `start-step` warnings and the `response.modelId` of the last `finish-step`. That id is the model that wrote the reply, which can differ from the requested one.
6. `toUIMessageStream` gets `messageMetadata`. On `start` it sends `{ reply: { connectionId, model, effort } }`, and on `finish` the full `ReplyRecord` with the outcome. `onEnd` passes the record to `upsertMessage`, which gains an optional `reply` argument and writes the four message columns.
7. On reload, `storedMessages` (`src/lib/messages.ts:231-240`) puts the record on `metadata.reply`. assistant-ui moves unknown metadata keys under `metadata.custom` (`node_modules/@assistant-ui/ai-sdk/src/converters/convertMessage.ts:59-70`), so the label reads `message.metadata.custom.reply`.

If slice 13 has merged, chain the tap after `stampReasoningTimes()` on the same stream.

### Routes

All take the session, parse bodies with zod, and return 404 for another user's id. Every helper takes `userId` first.

- `GET /api/connections` returns `PublicConnection[]`. `POST /api/connections` takes a discriminated union on `kind` with `label`, `apiKey`, and `baseUrl` for `openai-compatible`. It lists models before inserting and returns 502 "Could not reach the provider." without saving when that fails.
- `PATCH /api/connections/[id]` changes `label`, `baseUrl`, or `apiKey`. A new base URL needs a new key, the rule from `src/app/api/settings/route.ts:39-41`. `DELETE /api/connections/[id]` clears the chats and the defaults that use it, in one transaction.
- `GET /api/connections/[id]/models` returns `{ models: ListedModel[]; hidden: string[] }`. `PUT /api/connections/[id]/hidden-models` takes `{ modelId, hidden }`. The model id goes in the body because ids such as `openai/gpt-5` contain slashes.
- `GET` and `PUT /api/preferences/model` read and write the defaults.
- Delete `src/app/api/models/route.ts` and `credentialsForModelList` (`provider.ts:20-36`).
- `PUT /api/settings` drops `baseUrl`, `apiKey`, `model`, and `reasoningEffort` from its schema (`src/app/api/settings/route.ts:10-19`). `PublicSettings` drops `baseUrl`, `model`, `reasoningEffort`, and `keySet` (`src/lib/settings.ts:22-32`). Fix the `keySet` line in `AGENTS.md` and the key rule in `ARCHITECTURE.md` to name `GET /api/connections`.

### Boundaries

- Keys never leave the server. Only `connections.ts` decrypts, and only `languageModelFor` and `listModels` receive the plain key. Pass it to `sanitize` in every log line of the chat route, as today with `settings.apiKey`.
- Rows parse through zod at read time, `ProviderConnection` by `kind` and the chat triple as all-set or all-null. Code behind that trusts the types.
- No request carries Orbit's cookies to a provider. The providers get only the headers built in `provider.ts`.
- Base URLs stay any `http` or `https` URL here. Slice 18 adds the private-range check for `community` mode.

## Rules

Do:

- Encrypt every key on write and decrypt only at call time. Test that the database file does not contain the key bytes.
- Keep every effort rule in `effort.ts`. The UI asks `effortLevels`, the route asks `effortCallOptions` and `effortOutcome`.
- Label each reply with `response.modelId`, not the requested model.
- Migrate every caller of `/api/settings` provider fields and `/api/models` in this PR, and delete the old paths.
- Say in the README to back up `data/secret-key` with `orbit.db`. Without it the saved keys cannot be read.

Avoid:

- Anthropic's OpenAI-compatible URL. A connection of kind `openai-compatible` pointed at `api.anthropic.com` gets no special handling.
- Thinking budgets (`thinking.type: "enabled"` with `budgetTokens`). Current models reject them.
- A raw value in place of a token for any color or size.
- Holding the decrypted key in a module-level cache.

Open question for the maintainer. Anthropic recommends `fallbacks: "default"` for Claude Opus 5.5 and similar models, so a request declined by a safety classifier is retried on another model. `@ai-sdk/anthropic` 4.0.94 supports it and adds the beta header. It changes the model and the price of a reply without the user choosing, so this plan leaves it off and records `response.modelId`, which would show any switch. Turning it on is one line in `effortCallOptions`.
