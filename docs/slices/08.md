# Slice 8: Code sandbox

Let the model run short Python or JavaScript programs and read the output. Each run gets a fresh Docker container with no network, a read-only filesystem, a non-root user, and hard limits on CPU, memory, processes, and time.

**Branch** `feat/sandbox`. **Depends on** [slice 7](07.md) for the tool registry and the run card.

## Why

Models are bad at arithmetic, parsing, and anything that needs exact output. Running the code they write fixes that, because the model computes instead of guessing. The code is untrusted. It came from a model that read whatever the user pasted, and later from web search results. It must not reach the network, the host files, or the Orbit database.

## Scope

Ships:

- A `run_code` tool for `python` and `javascript`.
- A container per run with the limits in the design below.
- A run card that shows the code, stdout, stderr, the exit code, and the duration.
- `ORBIT_SANDBOX=on` to turn the tool on. It is off by default.

Does not ship:

- Packages beyond each image's standard library.
- Files that last between runs, or file upload.
- Output that streams while the code runs. The card shows a running state, then the full result.
- Remote Docker hosts.

## Design

### Data shape

```ts
type RunCodeInput = {
	language: "python" | "javascript";
	code: string; // at most 20,000 characters
};

type RunCodeOutput = {
	stdout: string; // at most 64 KB, then truncated
	stderr: string; // at most 64 KB, then truncated
	exitCode: number | null; // null when the run was killed
	durationMs: number;
	timedOut: boolean;
	truncated: boolean;
};
```

### The container contract

`containerSpec(input)` in `src/lib/sandbox/spec.ts` is a pure function. It returns the `dockerode` `createContainer` options. The model controls only `code` and `language`, never the options.

| Option | Value |
| --- | --- |
| `Image` | `python:3.13-slim` or `node:22-bookworm-slim`, pinned by digest in `src/lib/sandbox/images.ts` |
| `Cmd` | `["timeout", "-s", "KILL", "10", ...command]`, where `command` is `["python3", "-u", "-"]` or `["node", "-"]` from `src/lib/sandbox/images.ts`. The container stops itself at `RUN_TIMEOUT_SECONDS`, even when Orbit dies mid-run. The code arrives on stdin. |
| `User` | `65534:65534` (`nobody`) |
| `NetworkDisabled` | `true` |
| `HostConfig.NetworkMode` | `none` |
| `HostConfig.ReadonlyRootfs` | `true` |
| `HostConfig.Tmpfs` | `{ "/tmp": "rw,noexec,nosuid,size=64m" }` |
| `HostConfig.Memory`, `MemorySwap` | `268435456` (256 MiB) for both, so there is no swap |
| `HostConfig.NanoCpus` | `1000000000` (one CPU) |
| `HostConfig.PidsLimit` | `64` |
| `HostConfig.CapDrop` | `["ALL"]` |
| `HostConfig.SecurityOpt` | `["no-new-privileges"]` |
| `HostConfig.AutoRemove` | `false`. The runner removes the container itself after collecting its output. |
| `HostConfig.LogConfig` | `{ Type: "none", Config: {} }`. Output arrives through the attached stream so Docker does not retain unbounded logs. |

`runCode(docker, input, signal?)` in `src/lib/sandbox/run.ts` uses one ten-second deadline for container creation, attachment, startup, and execution. A timeout returns `timedOut`; cancellation uses the existing stopped-tool state. The lifecycle owns its container and removes it in `finally`. If a Docker setup call is still pending when the caller stops waiting, cleanup follows that call without sending the code. Normal completion waits for output and removal before returning `RunCodeOutput`. Docker API failures become `{ ok: false, error }` at the tool boundary.

### Docker access

During development the app talks to `/var/run/docker.sock` on the host. In Docker Compose the Orbit container needs a Docker API too. Mounting the socket gives the app root on the host. Use a socket proxy instead. Add a `docker-socket-proxy` service that allows only the container endpoints (`CONTAINERS=1`, `POST=1`, everything else `0`), and point `DOCKER_HOST` at it. The proxy limits which endpoints the app can call. It does not check the options sent to them, so `containerSpec` is the real guard. Write this trade-off in `SECURITY.md`.

The tool is off unless the server environment sets `ORBIT_SANDBOX=on`. That makes it the operator's decision, not a toggle in the browser.

## Rules

Do:

- Build container options only in `containerSpec`, and assert the whole object in `spec.test.ts`. The options Docker receives are the behavior.
- Remove every container, including after a timeout or a crash.
- Pull images in a separate step (`docker pull` with the pinned digest). A run with a missing image returns a clear error and does not pull.

Avoid:

- Passing any model-supplied value into `HostConfig`, `Env`, `Binds`, or `Cmd`.
- Mounting `/var/run/docker.sock` into the Orbit container.

## Build

### Turn 1. Reproduce, then write failing tests

1. Reproduce. Ask the real provider "What is the SHA-256 of the word orbit?" and save the answer. It cannot run code, so the hash is invented or missing. Compare it with `printf orbit | sha256sum`.
2. Write `spec.test.ts`. Assert every row of the contract table for both languages. Assert that `code` appears only in the stdin payload.
3. Write `run.test.ts`. Each case states what the code tries and what must happen.
   - `print(1+1)` prints `2` with exit code `0`.
   - `urllib.request.urlopen("http://1.1.1.1")` fails, and stderr names a network error.
   - Writing to `/etc/x` fails with a read-only filesystem error.
   - `import os; print(os.getuid())` prints `65534`.
   - Allocating 1 GiB is killed, and `exitCode` is `137` or `null`.
   - A fork loop stops at the process limit, and the host is fine.
   - `while True: pass` sets `timedOut` within 12 seconds.
   - After all cases, `docker ps -a --filter label=orbit.sandbox` lists nothing.
4. Write `sandbox.mjs`. Send `[qa:run-python]` and check for a code card with stdout `2`. Send `[qa:run-escape]` and check for a card with a network error. Run the tests and the scenario. They must fail because nothing exists yet.

### Turn 2. Make the tests pass

1. Pin both image digests and pull them.
2. Implement `containerSpec`, then `runCode`, then the tool and the card.
3. Add the socket proxy to Compose and run `run.test.ts` through it once.
4. Run `npm test`, `npm run typecheck`, and `npm run build`.

### Turn 3. Prove it with verify-orbit

1. Run `launch --mock` with `ORBIT_SANDBOX=on`, then `doctor`, `browse sandbox`, and `cleanup`.
2. Run `npm test` and post the `run.test.ts` lines for every escape case.
3. Ask the real provider the SHA-256 question again. The answer must match `sha256sum`.
4. Measure the time from `run_code` start to result for `print(1)`, 10 runs with the image already pulled. Report p50 and p95. The budget is a p95 under 1.5 seconds on this machine.
5. Post the output and the screenshots, update the changelog and the roadmap, and mark the PR ready.

## Done when

- `npm test`, `npm run typecheck`, and `npm run build` exit 0, and `run.test.ts` ran against a real Docker daemon.
- Every escape case fails the way the test names.
- No container is left behind after the test run or the scenario.
- The tool does not exist unless `ORBIT_SANDBOX=on`.
- Container start-to-result p95 is under 1.5 seconds.
