# Slice 5: Artifact panel

When the model writes an HTML page, an SVG, or a React component, show it running. A **Preview** button on the code block opens a side panel. The code runs in a locked-down frame that cannot touch the app.

**Branch** `feat/artifacts`. **Depends on** [slice 3](03.md) for the browse drive. **Refs** #11, "What Claude has that orbit doesn't", item 1.

## Why

Today a user who asks for a landing page, a chart, or a small tool gets a code block. To see it, they copy the code into a file and open it in a browser. Claude shows the result next to the chat. Issue #11 calls this the biggest single gap. `render_ui` from slice 2 covers structured cards. It cannot run code the model writes.

## Scope

Ships:

- A **Preview** action on fenced code blocks tagged `html`, `svg`, `jsx`, or `tsx`.
- A side panel with **Preview** and **Code** tabs and **Reload**, **Copy**, **Download**, and **Close** actions. On screens narrower than 1024 px the panel is a full-screen sheet.
- React components rendered with React 19.3.1 from esm.sh.
- Runtime errors from the frame shown under the preview, with a **Fix** action that fills the composer with the error.
- The open artifact in the URL, so a reload reopens it.
- One added sentence in the system prompt that asks for these code blocks.

Does not ship:

- Running Python or anything server-side. That is [slice 8](08.md).
- Saving artifacts outside the message. An artifact is a code block in a reply, so editing it uses the existing **Edit code** action.
- Imports from packages other than `react` and `react-dom`.
- Working offline for React. HTML and SVG work offline. React needs the browser to reach esm.sh.

## Design

### Data shape

An artifact is derived from a message. It is never stored on its own.

```ts
type ArtifactKind = "html" | "svg" | "react";

type Artifact = {
	key: string; // `${messageId}.${codeStart}`, codeBodyStart() plus the preceding text parts' lengths
	kind: ArtifactKind;
	code: string;
};

const KIND_BY_LANGUAGE: Record<string, ArtifactKind> = { html: "html", svg: "svg", jsx: "react", tsx: "react" };
```

Each code header registers the artifact derived from its parsed Markdown block. The panel reads `?artifact=<key>` from the URL and selects that registry entry. The registry is temporary and never stored. When you edit the code block, its entry changes and the frame reloads. Preview keys use full-message text offsets, while Edit code keeps its existing part-local offsets.

### The frame

`artifactDocument(kind, code): string` in `src/lib/artifacts/document.ts` is a pure function. It returns the full HTML for the frame's `srcdoc`.

- The frame element is `<iframe sandbox="allow-scripts" srcdoc=…>` with no other sandbox flags. Without `allow-same-origin` the frame has an opaque origin. It cannot read cookies, local storage, or the parent page, and it cannot call `/api/*` with the session.
- The document starts with this Content Security Policy in a `<meta http-equiv>` tag:
  `default-src 'none'; script-src 'unsafe-inline' https://esm.sh; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; connect-src 'none'`.
- A small inline script posts `{ type: "orbit-artifact-error", message }` to the parent on `error` and `unhandledrejection`. It also posts `{ type: "orbit-artifact-close" }` on Escape, because keyboard events inside the frame do not reach the app. The parent accepts a message only when `event.source` is that frame's `contentWindow` and the message passes its zod schema.
- For `react`, the panel turns JSX and TypeScript into JavaScript with Sucrase (`transforms: ["jsx", "typescript"]`, `jsxRuntime: "automatic"`). The document adds an import map for `react`, `react/jsx-runtime`, `react-dom`, and `react-dom/client`, each pinned to `19.3.1` on esm.sh. `artifactDocument` uses Sucrase's imports transform to handle default exports without rewriting strings, comments or regular expressions. Its module script exposes only these React modules through a frame-local import registry, rejects other imports, and renders the default export into `#root`. The React DOM URLs pin their React dependency to the same version.
- Load Sucrase and the document builder with dynamic `import()` in the panel, so the initial chat bundle does not include the compiler.

A prototype checked this design in headless Chrome. All three kinds rendered, a React button counted clicks, and in every frame `parent.document`, `document.cookie`, and `fetch` to the app origin were blocked. The prototype ran in a scratch folder and is not committed.

### Panel state

The panel is open when `?artifact=` is set. On a wide screen the chat column and the panel split the width, with the panel at 45 percent and at least 380 px. On a narrow screen the panel uses the existing `Dialog` as a full-screen sheet. Closing removes the parameter. Esc closes the panel.

### System prompt

Export `ARTIFACT_INSTRUCTIONS` from `src/lib/artifacts/detect.ts`, and join it after `RENDER_UI_SYSTEM` in the route's `instructions`. The text:

> For a page, chart, game, or interactive component, write one complete fenced code block tagged html, svg, or jsx. A jsx block imports only from react and default-exports one component.

## Rules

Do:

- Keep `allow-scripts` as the only sandbox flag. Test that.
- Build the frame document only in `artifactDocument`, and test it as a string.
- Check `event.source` on every message from the frame.

Avoid:

- Adding `allow-same-origin`, `allow-popups`, `allow-top-navigation`, or `allow-forms`. Any one of them gives the model's code a way out of the frame.
- Evaluating artifact code in the app's own window, even for a quick check.

## Build

### Turn 1. Reproduce, then write failing tests

1. Reproduce the gap. Write `artifacts.mjs`. It sends `[qa:artifact-html]`, checks for a **Preview** button on the code block, clicks it, and checks that a frame shows the heading from the mock reply. Run it on `main`. It must fail because there is no **Preview** button. Save `before.png`.
2. Extend the scenario with the other kinds and the security checks. For SVG, check that the frame contains an `svg` element. For React, click the counter button and check that its text changes. For each frame, run `frame.evaluate` and check that `parent.document` throws, `document.cookie` throws, and a `fetch` to the app origin rejects. For `[qa:artifact-error]`, check that the error text shows under the preview. Then reload and check that the panel is open again.
3. Write `document.test.ts`. Check that every kind's document has the exact CSP string, that `react` has an import map pinned to `19.3.1`, that an anonymous default export renders, and that `artifactKind` returns `undefined` for `python`. Add a render test showing that the frame element's `sandbox` attribute is exactly `allow-scripts`. Run `npm test`. The new tests must fail.

### Turn 2. Make the tests pass

1. Implement `detect.ts` and `document.ts`.
2. Build the frame, the panel, and the **Preview** action. Then add the URL state and the narrow-screen sheet.
3. Add the instructions to the route.
4. Run `npm test`, `npm run typecheck`, and `npm run build`.

### Turn 3. Prove it with verify-orbit

1. Run `launch --mock`, `doctor`, `browse artifacts`, and `cleanup`.
2. Ask a real provider for "a small HTML page with a button that changes color", open the preview, click the button, and take a screenshot.
3. Post the output and the screenshots, update the changelog and the roadmap, and mark the PR ready.

## Done when

- `npm test`, `npm run typecheck`, and `npm run build` exit 0.
- HTML, SVG, and React code blocks preview and respond to clicks.
- The frame cannot read the parent page or cookies, and cannot fetch the app origin. The scenario proves each of these.
- A runtime error shows under the preview, and **Fix** fills the composer with it.
- A reload reopens the panel. Esc and **Close** close it.
- The panel works at 1440×900 and 390×844 with no horizontal page scroll.
