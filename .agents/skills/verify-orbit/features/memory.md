# Memory

Run `node .agents/skills/verify-orbit/verify.mjs launch --mock` with `ORBIT_OLLAMA_URL` pointing at `scripts/qa/mock-ollama.mjs`. Then run `doctor`, `browse memory`, and `cleanup`.

The browser sends `[qa:remember] I deploy to Fly.io`. The mock provider calls `remember`. The memory line reads "Saved to memory" and shows that text after the label. `/memory` lists that fact and shows **Embeddings on**. A new chat sends `[qa:plain] Where should hosting live?` so the mock answers `pong`. The next mock request carries `I deploy to Fly.io` as quoted notes on the user message, and the system message does not contain that text. Opened in `Pacific/Kiritimati` and `Pacific/Pago_Pago`, two browser zones 25 hours apart, `/memory` shows that memory's date in each reader's zone and raises no page error, such as React's hydration error #418. A 500 character memory with no spaces stays inside the memory line, cut with an ellipsis, and inside the border of the `/memory` row, on desktop and at 390 by 844. The check compares the text's lines with that border, not the paragraph's own width, because Chrome can end a line 1px past its paragraph where it breaks a word between kerned letters. With wrapping turned off on that text, the same check fails. An edit of 501 characters shows the server's reason. A shorter edit changes the text. With the browser dropping memory requests, Save shows `Could not save`, Delete closes its dialog and shows `Could not delete`, and the page raises no error. With eight more memories, the list scrolls at 1280 by 800. A failed save or delete on the last row shows its error line, with `role="alert"`, inside that row and on screen. The scenario then deletes those eight memories. With the mock set to fail, the page shows the Ollama error and recall still has full text search. Delete asks once. The next chat does not send the deleted text.

The request labels the Fly.io note as one the assistant saved. After the Memory page edit, the scenario asks about Render in a new chat and checks that the request credits the edited note to the user. Both requests keep the saved text in the user message.
